# state-definitions Specification

## Purpose

開発者が`.gls`ファイルに状態の識別子、名前、意味、カラーを記述し、定義した内容と順序をプレビューで共有できるように、状態定義の記法、有効な入力、解析結果を定める。

## Requirements

### Requirement: REQ-001 - 状態定義の読み取り

WHEN `.gls`の内容を解析するとき、DSL解析機能は、行頭の`State <ID> as "<状態名>" color "<#RRGGBB>":`と、その直後の半角空白4個で始まる1行以上の意味を状態として読み取り、ID、状態名、意味、カラーを定義順に返さなければならない(SHALL)。\
IDは`[A-Za-z_][A-Za-z0-9_]*`に一致し、状態名は空白だけではない文字列、カラーは`#`と大小文字を区別しない6桁の16進数字とする。\
状態名の引用符内に改行と二重引用符は使えず、エスケープ構文は設けない。\
意味はインデントを除いて改行で連結し、空白だけではない内容を必要とする。\
LFとCRLFを受け付け、空白だけの行は場所によらず無視し、空の文書は状態0件として返す。

#### Scenario: REQ-001-S01 - 状態の各項目を読み取る

- **GIVEN** 次の`.gls`内容がある。

  ```gls
  State IDLE as "待機" color "#4F46E5":
      開始を待つ状態
  ```

- **WHEN** 内容を解析する。
- **THEN** 状態は1件で、IDは`IDLE`、状態名は`待機`、意味は`開始を待つ状態`、カラーは`#4F46E5`である。
- **AND** エラーはない。

#### Scenario: REQ-001-S02 - 複数行の意味と改行形式を扱う

- **GIVEN** 同じ状態定義を次の改行形式で記述し、意味の各行を半角空白4個で下げている。

  | 改行形式 | 意味の各行 | 行間の空白だけの行 | 期待する意味 |
  | --- | --- | --- | --- |
  | LF | `開始を待つ`、`要求で実行へ進む` | あり | `開始を待つ`と`要求で実行へ進む`をLFで連結した文字列 |
  | CRLF | `開始を待つ`、`要求で実行へ進む` | なし | `開始を待つ`と`要求で実行へ進む`をLFで連結した文字列 |

- **WHEN** 各内容を解析する。
- **THEN** 意味は表の期待する意味と一致し、エラーはない。

#### Scenario: REQ-001-S03 - 状態がない文書を扱う

- **GIVEN** `.gls`の内容が空、または空白と改行だけである。
- **WHEN** 内容を解析する。
- **THEN** 状態は0件で、エラーはない。

#### Scenario: REQ-001-S04 - 状態の識別と定義順を保持する

- **GIVEN** IDが`_Z9`、`A_FIRST`の順に2件の状態を定義し、両方の状態名を`待機`にしている。
- **WHEN** 内容を解析する。
- **THEN** 状態は`_Z9`、`A_FIRST`の順に返され、同じ状態名でも2件の独立した定義として扱われる。
- **AND** エラーはない。

### Requirement: REQ-002 - 不正な状態定義の報告

IF 状態宣言の構文、ID、状態名、カラー、意味のインデントや内容がREQ-001の範囲を外れる、IDが重複する、または状態定義、REQ-007のイベント、REQ-008の遷移、REQ-022の有効なEventCategoryHeaders宣言、REQ-028の有効なStateGroup宣言のいずれにも属さない記述がある場合、THEN DSL解析機能は、該当行と理由を持つエラーを返し、その文書の状態定義を正常な結果として返してはならない(SHALL)。\
意味の非空行は半角空白4個だけでインデントし、タブやそれ以外の深さを許可しない。\
IDは大文字と小文字を区別して重複を判定し、必須の宣言要素や意味を省略できない。

#### Scenario: REQ-002-S01 - 不正な入力の位置と理由を返す

- **GIVEN** 正常な状態定義のうち、次の箇所だけを不正にした内容がある。

  | 不正な箇所 | 入力例 | エラーの対象 |
  | --- | --- | --- |
  | 宣言の要素不足 | `as "待機"`を省略 | 宣言行の構文 |
  | 宣言末尾 | `:`を省略 | 宣言行の構文 |
  | ID | `1IDLE` | 宣言行のID |
  | 状態名 | `""`、`"   "` | 宣言行の状態名 |
  | 状態名の引用符 | 閉じる`"`を省略 | 宣言行の構文 |
  | 状態名の改行 | 引用符を閉じる前に改行 | 宣言行の構文 |
  | 状態名の途中の引用符 | 名前の途中に`"`を入れる | 宣言行の構文 |
  | カラー | `"red"`、`"#FFF"`、`"#GG0000"` | 宣言行のカラー |
  | カラーの不足 | `color "#4F46E5"`を省略 | 宣言行の構文 |
  | 意味の不足 | 宣言直後が文書末尾 | 意味を欠く宣言行 |
  | 意味の内容 | 意味を空白だけにする | 意味を欠く宣言行 |
  | 意味のインデント | 半角空白2個、8個、タブ1個 | 意味の行のインデント |
  | 未対応の記述 | 独立した`Group STATES`の行 | 未対応の行 |

- **WHEN** 各内容を解析する。
- **THEN** 表の対象行を指すエラーと、構文、ID、状態名、カラー、意味、インデント、未対応の記述のうち該当する理由が返る。
- **AND** 正常な状態定義の結果は返らない。

#### Scenario: REQ-002-S02 - 重複したIDを報告する

- **GIVEN** 2件の状態のIDがともに`IDLE`である。
- **WHEN** 内容を解析する。
- **THEN** 2件目の宣言行にIDの重複を示すエラーが返る。
- **AND** 正常な状態定義の結果は返らない。

#### Scenario: REQ-002-S03 - IDの大文字と小文字を区別する

- **GIVEN** 2件の状態のIDが`IDLE`と`idle`である。
- **WHEN** 内容を解析する。
- **THEN** 状態は2件で、それぞれのIDが保持され、重複エラーはない。

### Requirement: REQ-028 - 名前付き状態グループの読み取り

WHEN `.gls`を解析するとき、DSL解析機能は、行頭の`StateGroup <ID> as "<グループ名>":`と、半角空白4個で下げた1行1件の状態IDを読み取り、グループID、名前と所属状態IDを宣言順に返さなければならない(SHALL)。\
所属は異なる宣言済み状態2件以上とし、宣言の前後関係を問わず、1状態は最大1グループに所属できる。\
ID形式、名前の引用符と非空白、改行と空白行の制約はREQ-001と同じで、キーワード間は半角空白1個以上、行末の半角空白を許可する。\
グループIDは状態とイベントから独立した名前空間で大小文字を区別し、同名の別グループを許可する。\
グループは省略でき、状態とイベント、遷移を変更せず、グループの入れ子は認めない。

#### Scenario: REQ-028-S01 - 名前と所属状態を読み取る

- **GIVEN** 宣言済み状態`IDLE`、`RUNNING`と、次の定義がある。

  ```gls
  StateGroup ACTIVE as "稼働系":
      IDLE
      RUNNING
  ```

- **WHEN** 内容を解析する。
- **THEN** グループは1件で、IDは`ACTIVE`、名前は`稼働系`、所属状態IDは`IDLE`、`RUNNING`の順であり、状態の内容と順序は変わらず、診断はない。

#### Scenario: REQ-028-S02 - 後方参照と空白を保持する

- **GIVEN** 状態宣言より前に2つのグループを定義し、グループ宣言順は`Z_GROUP`、`A_GROUP`、最初の所属ID順は`B`、`A`である。
- **AND** 名前は` A > B `であり、文書はCRLF、空白行、複数のキーワード間空白と行末空白を含む。
- **WHEN** 内容を解析する。
- **THEN** グループ順と所属ID順、名前の前後の空白と`>`は保持され、後方の状態参照を解決し、診断はない。

#### Scenario: REQ-028-S03 - IDと表示名の名前空間を区別する

- **GIVEN** 状態IDとイベントIDに`ACTIVE`があり、グループIDを`ACTIVE`、`active`の順で定義し、それぞれ異なる2状態を所属させ、グループ名はともに`稼働系`である。
- **WHEN** 内容を解析する。
- **THEN** 状態とイベントは元のままで、2グループのIDと所属は独立して保たれ、同名やIDの大小文字による統合と重複診断はない。

#### Scenario: REQ-028-S04 - グループなしの既存モデルを維持する

- **GIVEN** グループ宣言のない既存の状態だけの文書、分類と条件分岐のある文書、空文書のいずれかである。
- **WHEN** 内容を解析する。
- **THEN** 状態、イベント、分類列見出し、分岐なしと分岐付き遷移の内容とモデルの形は既存と完全一致し、空のグループ項目を補わず、診断はない。

### Requirement: REQ-029 - 状態グループの構造と所属の誤りの報告

IF グループがREQ-028の構文と制約を外れる場合、THEN DSL解析機能は、該当行と理由を診断し、文書全体を正常なモデルとして返してはならない(SHALL)。\
宣言の構文、IDと名前、2状態未満の所属はグループ宣言行、不正な所属IDの形式と未宣言参照、所属行の構文とインデントはその行を指す。\
同じグループIDの重複は後の宣言行、同じグループ内の重複所属と複数グループへの所属は後の所属行を指す。\
グループ宣言をインデントした入れ子と、グループだけのIDを遷移の状態参照に使うことを拒否し、不正な所属の削除や状態の補完によって受理しない。

#### Scenario: REQ-029-S01 - 宣言と本文の不正を元の行で診断する

- **GIVEN** 有効なグループの1か所だけを次のいずれかに変えている。

  | 誤り | 診断対象と理由 |
  | --- | --- |
  | as、引用符、名前、末尾コロンの不足や途中の引用符と改行 | 宣言行、構文 |
  | グループIDが1BAD、名前が空または空白だけ | 宣言行、IDまたは名前 |
  | 所属が0件、空白行だけ、または1状態だけ | 宣言行、2状態以上が必要 |
  | 所属行が1BAD | 所属行、状態IDの形式 |
  | 1行にA BやA,Bを記述する | 所属行、1行1件の状態IDが必要 |
  | 所属を2個、8個の空白またはタブで下げる | 所属行、インデント |
  | 下げたStateGroup宣言とその本文を置く | 子の宣言行、入れ子または所属行の構文 |

- **WHEN** 各内容を解析する。
- **THEN** 表の位置と理由の診断があり、正常なモデルはなく、状態の意味や処理本文としての読み替えはない。

#### Scenario: REQ-029-S02 - 所属状態の参照だけを解決する

- **GIVEN** ほかの所属は有効で、1件だけを未宣言の`MISSING`、または状態としては未宣言で別グループにだけ存在するIDへ変更している。
- **WHEN** 内容を解析する。
- **THEN** 変更した所属行に状態IDの未宣言参照を示す診断があり、グループの中身への展開や不足する状態の生成はなく、正常モデルは返らない。

#### Scenario: REQ-029-S03 - 重複の種類を後の宣言位置で診断する

- **GIVEN** 次のいずれかの重複だけがある。

  | 重複 | 診断対象 |
  | --- | --- |
  | 同じグループIDを2回宣言 | 後のStateGroup宣言行 |
  | 同じグループ内で同じ状態IDを2回指定 | 後の所属行 |
  | 2つのグループへ同じ状態IDを所属 | 後のグループの所属行 |

- **WHEN** 内容を解析する。
- **THEN** 対象行に重複の種類とIDを示す診断があり、統合や後勝ちで受理せず、正常モデルはない。

#### Scenario: REQ-029-S04 - グループを個々の状態の参照に置き換えない

- **GIVEN** `ACTIVE`はグループとしてだけ宣言済みであり、分岐なし遷移の遷移元、遷移先、または分岐の遷移先の1か所だけに`ACTIVE`を指定している。
- **WHEN** 各内容を解析する。
- **THEN** 対象のTransition行またはBranch行に未宣言の状態ID`ACTIVE`の診断があり、グループの全状態への遷移を生成せず、正常モデルはない。

# state-transition-diagram Specification

## Purpose

開発者が既存のVS Codeプレビュー内で状態間の関係を俯瞰できるように、状態名と指定カラーを持つノード、方向付きの淡い矢印、自己ループと3表示の更新の整合を定める。

## Requirements

### Requirement: REQ-014 - 状態定義表と状態遷移表の間の状態ノード

WHEN 有効な文書をプレビューするとき、プレビューは、状態定義表と状態遷移表の間に状態遷移図を表示し、各状態IDに対応するノードへ状態名と指定カラーを反映しなければならない(SHALL)。\
同じ状態名でも異なるIDのノードを統合せず、遷移やイベントを持たない状態も表示する。\
状態名は表示用テキストとして扱い、状態グループの枠と所属状態の表示はREQ-030に従う。\
状態が0件の有効な文書ではノードと矢印を表示せず、状態がないことを案内し、以前の図を残さない。

#### Scenario: REQ-014-S01 - 2表の間に名前と指定色を持つノードを表示する

- **GIVEN** 状態`Z_IDLE`(待機、`#4F46E5`)、`A_RUN`(実行中、`#22C55E`)を定義している。
- **WHEN** プレビューを開く。
- **THEN** 上から状態定義表、状態遷移図、状態遷移表の順で表示される。
- **AND** 図には`待機`と`実行中`のノードが各1件あり、それぞれのノードに対応する指定カラーが使われ、名前の代わりにIDは表示されない。

#### Scenario: REQ-014-S02 - 同じ名前でも状態IDを区別する

- **GIVEN** 異なるIDの状態2件の名前がともに`待機`で、それぞれから異なる状態への遷移がある。
- **WHEN** 図を表示する。
- **THEN** `待機`のノードは2件あり、それぞれの矢印は遷移元IDに対応するノードから出て、名前によって1件へ統合されない。

#### Scenario: REQ-014-S03 - イベントや遷移のない状態も表示する

- **GIVEN** 状態2件があり、次のいずれかの内容である。

  | 内容 | 期待する図 |
  | --- | --- |
  | イベントも遷移もない | 状態ノード2件、矢印0本 |
  | イベントがあり遷移がない | 状態ノード2件、矢印0本 |
  | 1件の状態だけに自己遷移がある | 状態ノード2件、自己ループ1本 |

- **WHEN** 図を表示する。
- **THEN** 図は表の結果となり、遷移のない状態が欠落しない。

#### Scenario: REQ-014-S04 - 状態がなくなったら古い図を消す

- **GIVEN** ノードと矢印を持つ図を表示している。
- **WHEN** 文書を空にする、またはイベントだけの有効な内容へ変更する。
- **THEN** 図領域には状態がないことの案内があり、ノードと矢印は0件で、以前の状態名は残らない。

#### Scenario: REQ-014-S05 - 状態名を文字列として表示する

- **GIVEN** 状態名に`<script>window.glsDiagramExecuted = true</script>`を持つ状態と、`<b>待機</b>`を持つ状態がある。
- **WHEN** 図を表示する。
- **THEN** 両方の名前の文字列がそのまま表示され、図内に`script`要素や`b`要素は生成されず、`window.glsDiagramExecuted`は設定されない。

### Requirement: REQ-015 - 状態間の方向付き矢印

WHEN 状態遷移図を表示するとき、図は、分岐なし遷移とREQ-026の各分岐が持つ遷移先状態IDを遷移元ノードから遷移先ノードへの矢印として表示しなければならない(SHALL)。\
処理の有無によらず遷移先で矢印の有無を決め、遷移なしと未定義の組み合わせには矢印を作らない。\
同じ遷移元IDと遷移先IDの組み合わせはイベントが異なっても1本にまとめ、逆方向は別の矢印とする。\
自状態への遷移は外側へ張り出して同じノードへ戻る自己ループとし、相互の矢印は方向を区別できる経路にする。\
イベント名、条件名と処理のラベルは表示しない。\
REQ-031の集約対象だけは遷移元ノードの代わりにグループ枠を始点とし、到達先は個々の状態ノードのままにする。

#### Scenario: REQ-015-S01 - 遷移先へ向く矢印をラベルなしで表示する

- **GIVEN** 状態`IDLE`と`RUNNING`があり、イベント`START`(開始要求)に対して`IDLE`から`RUNNING`へ処理`開始を記録する`を定義している。
- **WHEN** 図を表示する。
- **THEN** 矢印は1本で、始点は`IDLE`のノード、終点の矢尻は`RUNNING`のノードにある。
- **AND** 図には`開始要求`、`START`、`開始を記録する`のラベルがない。

#### Scenario: REQ-015-S02 - 遷移なしと未定義を矢印へ変換しない

- **GIVEN** 状態`IDLE`、`RUNNING`とイベント`START`があり、対象の組み合わせは次のいずれかである。

  | 定義 | 期待する矢印 |
  | --- | --- |
  | 処理なし、遷移先RUNNING | IDLEからRUNNINGへの1本 |
  | 処理あり、遷移なし | 0本 |
  | 処理なし、遷移なし | 0本 |
  | 定義がない | 0本 |

- **WHEN** 図を表示する。
- **THEN** 矢印は表の結果となり、遷移なしや未定義から自己ループは作られない。

#### Scenario: REQ-015-S03 - 同じ向きの状態間の関係をまとめる

- **GIVEN** 異なるイベント`START`、`RETRY`でともに`IDLE`から`RUNNING`へ遷移し、処理は異なっている。
- **WHEN** 図を表示する。
- **THEN** `IDLE`から`RUNNING`への矢印は1本だけで、イベントや処理の違いによって重複しない。
- **AND** 状態遷移表では各イベントの処理と遷移先が別々のセルに保持される。

#### Scenario: REQ-015-S04 - 自状態への遷移を自己ループで示す

- **GIVEN** 異なるイベント2件でともに`IDLE`から`IDLE`へ遷移している。
- **WHEN** 図を表示する。
- **THEN** `IDLE`から出てノード外側を通り、矢尻が`IDLE`へ戻る自己ループが1本あり、長さ0の線や別の状態への矢印にはならない。

#### Scenario: REQ-015-S05 - 相互の遷移を区別する

- **GIVEN** `IDLE`から`RUNNING`と、`RUNNING`から`IDLE`の遷移がある。
- **WHEN** 図を表示する。
- **THEN** 矢印は2本あり、それぞれの終点に矢尻があり、経路が完全には重ならず、両方向の存在を確認できる。

### Requirement: REQ-016 - 状態を主役にした図の配色

WHEN 状態遷移図を表示するとき、図は、矢印の線と矢尻を淡い色でそろえ、VS Codeの明暗テーマに追従する背景上で、状態名、指定カラー、矢印の方向を読み取れるようにしなければならない(SHALL)。\
矢印を状態カラーやイベントごとの強い色で塗り分けない。

#### Scenario: REQ-016-S01 - 矢印の線と矢尻に共通の淡い配色を使う

- **GIVEN** 異なる指定カラーを持つ状態間の矢印と自己ループがある。
- **WHEN** 図を表示する。
- **THEN** 通常の矢印と自己ループの線と矢尻は共通の淡い配色であり、状態の指定カラーを矢印へ転用しない。

#### Scenario: REQ-016-S02 - 明暗テーマで状態と方向を確認できる

- **GIVEN** 指定カラー付きの状態ノードと通常の矢印、自己ループを含む図を表示している。
- **WHEN** VS CodeのDark+とLight+を切り替える。
- **THEN** 図の背景と基本の文字色はテーマに追従し、状態名と淡い矢印の方向を読み取れ、状態の指定カラーは保たれる。

### Requirement: REQ-017 - 3表示を同じ現在の文書へ追従させる

WHEN プレビュー対象の内容が変わるとき、プレビューは、REQ-003、REQ-005、REQ-006、REQ-013の対象文書、保存前の更新、古い結果の拒否、診断と正常表示の保持を状態遷移図にも適用し、両方の表と図を同じ正常な内容から表示しなければならない(SHALL)。\
正常な内容がない文書では他の文書の図を表示しない。\
修正後は3表示を現在の内容へ更新し、診断とエラー案内を消す。\
同じURIを小さい版番号で開き直しても自動更新とコマンド再実行を受け付け、表示準備中の編集は準備完了時に反映する。

#### Scenario: REQ-017-S01 - 未保存の変更を図と両方の表へ反映する

- **GIVEN** 同じ文書の状態定義表、図、状態遷移表を表示し、保存は行わない。
- **WHEN** 次のいずれかの編集を行う。

  | 編集 | 図の期待する結果 |
  | --- | --- |
  | 状態名とカラーを変更する | 対象ノードの名前とカラーが変わる |
  | 参照されていない状態を追加、削除する | 対象ノードが増減する |
  | 遷移先を別の有効な状態IDへ変更する | 元の矢印が消え、新しい遷移先へ向く |
  | 遷移先をなしにする | 対象の状態間の矢印が消える |
  | 同じ向きの最後の遷移を削除する | 対象の矢印が消える |
  | 同じ向きの複数の遷移のうち1件だけを削除する | 対象の矢印は1本のまま残る |
  | 遷移なしから自状態への遷移へ変更する | 自己ループが1本現れる |
  | イベント名や処理だけを変更する | ノードと矢印の関係は変わらない |

- **THEN** 手動更新なしで図は表の結果となり、両方の表も同じ編集後の定義に従い、文書は未保存のままである。

#### Scenario: REQ-017-S02 - 参照エラーで3表示を保つ

- **GIVEN** 正常な3表示を表示している。
- **WHEN** 遷移先を未宣言の`MISSING`へ変更する。
- **THEN** Problemsには遷移宣言行を指す参照エラーがあり、図と両方の表は直前の正常な名前、カラー、処理、矢印と遷移先を保つ。

#### Scenario: REQ-017-S03 - 保持した正常表示から修正後の3表示へ回復する

- **GIVEN** 正常な3表示の後に参照エラーとなり、診断とエラー案内があり、3表示は直前の正常な内容を保持している。
- **WHEN** 保存せず、状態名と処理を以前とは異なる内容にし、遷移先を以前と異なる有効な状態IDへ修正する。
- **THEN** 図の状態名と矢印の終点、両方の表の状態名、処理、遷移先は修正後の内容で一致し、以前の正常な内容には戻らない。
- **AND** 診断とエラー案内は消え、文書は未保存のままである。

#### Scenario: REQ-017-S04 - 不正な別文書へ切り替えたら以前の図を表示しない

- **GIVEN** 正常なA.glsの3表示を表示し、B.glsには未宣言IDへの参照があり、一度も正常に表示していない。
- **WHEN** B.glsからプレビューコマンドを実行する。
- **THEN** B.glsの参照診断と表示できないことの案内があり、A.glsのノード、矢印と両方の表のデータは残らない。

#### Scenario: REQ-017-S05 - 遅れた古い解析結果と通知を使わない

- **GIVEN** 最新の状態名、処理と遷移先を反映した3表示と診断がある。
- **WHEN** 古い内容の解析結果、表示通知または図の表示準備完了が遅れて届く。
- **THEN** 3表示と診断は最新のままで、古い状態名、矢印、処理、遷移先、エラーへ戻らない。

#### Scenario: REQ-017-S06 - 小さい版番号で再オープンしても更新する

- **GIVEN** プレビューを残して文書を閉じ、同じURIを閉じる前より小さい版番号で開き直している。
- **WHEN** 次のいずれかの操作を行う。

  | 操作 | 期待する結果 |
  | --- | --- |
  | コマンドを再実行せず状態名と遷移先を未保存で変更する | 同じプレビューの3表示が編集後の内容になる |
  | 再オープンした文書からコマンドを実行する | 既存の単一プレビューの3表示が現在の内容になる |

- **THEN** 閉じる前より小さい版番号のままでも期待する結果となり、閉じる前のノード、矢印と表のデータは残らない。

#### Scenario: REQ-017-S07 - 表示準備中の変更を最初の図へ反映する

- **GIVEN** プレビューの表示準備が完了する前に、状態名`待機`を`準備中の編集`にし、遷移先を別の有効な状態IDへ未保存で変更している。
- **WHEN** 図の表示準備が完了する。
- **THEN** 最初に表示する3表示は`準備中の編集`と変更後の遷移先に対応し、古いノードや矢印を表示するための追加の編集やコマンド再実行は不要である。

#### Scenario: REQ-017-S08 - 別の文書の編集を混入させない

- **GIVEN** A.glsの3表示を表示している。
- **WHEN** 別のB.glsの状態名と遷移先を編集する。
- **THEN** 対象はA.glsのままで、3表示と診断はB.glsの内容に変化しない。

### Requirement: REQ-026 - 各分岐の到達先を状態間の矢印へ反映する

WHEN 分岐付き遷移を図に表示するとき、図は、各分岐の遷移先状態IDを元の状態からの有向ペアへ変換し、REQ-015の矢印として表示しなければならない(SHALL)。\
共通処理と各分岐の処理の有無によらずすべての分岐を対象とし、同じ有向ペアは分岐とイベント、分岐の有無をまたいで1本へまとめる。\
REQ-031のグループ集約条件を満たす有向ペアだけは枠から到達先への1本にまとめ、個々の分岐定義は維持する。\
遷移なしから矢印を作らず、自己遷移と逆方向はREQ-015に従う。\
状態ノードの名前とカラー、淡い矢印と矢尻を保ち、条件名、イベント名、共通処理と分岐の処理のラベル、条件用ノードは追加しない。

#### Scenario: REQ-026-S01 - すべての分岐の異なる遷移先へ矢印を作る

- **GIVEN** `IDLE`から`START`で、共通処理と、`準備完了`(開始する、RUNNING)、`異常`(処理なし、FAILED)の2分岐を定義している。
- **WHEN** 図を表示する。
- **THEN** `IDLE`から`RUNNING`と`IDLE`から`FAILED`への矢印がそれぞれ1本あり、矢尻は各終点へ向き、2つ目の分岐や処理なしの分岐も省略されない。
- **AND** 状態ノードだけが存在し、状態名とカラーを保ち、共通処理、条件名、イベント名と分岐の処理のラベルはない。

#### Scenario: REQ-026-S02 - 分岐と既存遷移の同じ有向ペアを集約する

- **GIVEN** `START`の異なる条件2件と、分岐なしの`RETRY`がすべて`IDLE`から`RUNNING`へ遷移する。
- **WHEN** 図を表示する。
- **THEN** `IDLE`から`RUNNING`への矢印は1本だけで、表には元の2分岐と分岐なしセルの処理が別々に残る。

#### Scenario: REQ-026-S03 - 分岐でも遷移なし、自己遷移と逆方向を区別する

- **GIVEN** 次のいずれかの遷移を定義している。

  | 定義 | 期待する矢印 |
  | --- | --- |
  | IDLEの分岐の遷移先がすべて`-` | 0本 |
  | IDLEの分岐の遷移先がIDLEと`-` | IDLEの外側を通ってIDLEへ戻る自己ループ1本 |
  | IDLEの分岐がRUNNINGへ、分岐なし遷移がRUNNINGからIDLEへ | 完全には重ならない両方向の2本 |

- **WHEN** 図を表示する。
- **THEN** 表の結果だけがあり、自己ループや通常の矢印、相互遷移の各矢尻がそれぞれの経路終端の進行方向と一致し、遷移なしから自己ループは作られない。

### Requirement: REQ-030 - 所属状態を囲む名前付きの実線枠

WHEN 有効な状態グループをプレビューするとき、状態遷移図は、グループ名を持つ実線の枠で所属する状態ノードだけを囲み、個々の状態名と指定カラーを保持しなければならない(SHALL)。\
同名の状態とグループはIDで区別し、未所属状態はどの枠にも含めず、各グループと未所属状態の領域を重ねない。\
所属状態は状態の定義順に配置し、枠内に名前と状態、内部の自己ループを欠落なく収め、グループ名は表示用テキストとして扱う。\
状態定義表と状態遷移表の間という配置とテーマに沿う表示を保ち、グループ宣言がなければ既存の図を維持する。\
表示範囲はREQ-040、状態定義表からの状態選択の表示はREQ-036に従い、図からの状態選択とグループ選択は追加せず、操作部はREQ-038の縮小、Reset、拡大とREQ-041の画像保存に従う。

#### Scenario: REQ-030-S01 - 指定した状態だけを実線の枠で囲む

- **GIVEN** 定義順が`A`、未所属`X`、`B`、`C`の状態があり、グループ`G`(稼働系)の所属は`C`、`A`、`B`の順で指定している。
- **WHEN** 図を表示する。
- **THEN** `稼働系`の実線枠は1つで、内部の状態は定義順の`A`、`B`、`C`の各1件であり、それぞれの名前と指定カラーが保たれる。
- **AND** `X`は枠外にあり、枠は状態定義表と状態遷移表の間にだけ表示される。

#### Scenario: REQ-030-S02 - 同名グループと名前の文字列を区別する

- **GIVEN** 異なるIDのグループ2件が同じ名前`<b>稼働系</b>`で、それぞれの所属状態は異なり、同名状態もある。
- **WHEN** 図を表示する。
- **THEN** 同名グループの実線枠は2つで重ならず、状態の統合と混入はなく、グループ名の文字列は各枠にそのまま表示され、b要素は作られない。

#### Scenario: REQ-030-S03 - 長い名前と実測した状態とループを枠に収める

- **GIVEN** 折り返しが必要な長いグループ名と複数行の状態名、上へ張り出す自己ループを持つグループと、別グループと未所属状態がある。
- **WHEN** 初回に図の配置が完了する。
- **THEN** グループ名の末尾、所属状態の全領域と自己ループの経路が枠内に収まり、名前と状態は重ならず、別グループと未所属状態は枠外である。
- **AND** 枠とノード、矢印は図領域内へ収まり、長い内容を省略せず、状態定義表からの選択表示を除き、図からの状態選択とグループ選択はなく、操作ボタンはREQ-038の縮小、Reset、拡大とREQ-041の画像保存だけである。

#### Scenario: REQ-030-S04 - グループの除去で従来の図へ戻す

- **GIVEN** グループ枠と所属状態を表示している。
- **WHEN** 有効なままグループ宣言だけをすべて除去する。
- **THEN** 枠とグループ名は残らず、全状態の名前とカラー、定義順の配置は同じ内容のグループなし文書と一致する。

### Requirement: REQ-031 - 複数の所属状態から同一外部状態への矢印集約

#### Scenario: REQ-031-S01 - 一部のメンバーだけの共通到達先も枠から1本にする

### Requirement: REQ-043 - 保存対象と非同期の結果の整合

WHEN 図の保存を進めるとき、プレビューは、対象文書と表示済みの内容を照合し、受理した1件の保存要求に対応する画像だけを保存しなければならない(SHALL)。\

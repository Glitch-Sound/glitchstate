# state-transition-diagram Specification

## Purpose

開発者が既存のVS Codeプレビュー内で状態間の関係を俯瞰できるように、状態名と指定カラーを持つノード、方向付きの淡い矢印、自己ループと3表示の更新の整合を定める。

## Requirements

### Requirement: REQ-014 - 状態定義表と状態遷移表の間の状態ノード

WHEN 有効な文書をプレビューするとき、プレビューは、状態定義表と状態遷移表の間に状態遷移図を表示し、各状態IDに対応するノードへ状態名と指定カラーを反映しなければならない(SHALL)。\
同じ状態名でも異なるIDのノードを統合せず、遷移やイベントを持たない状態も表示する。\
状態名は表示用テキストとして扱い、状態グループの枠と所属状態の表示はREQ-030に従う。\
状態が0件の有効な文書ではノードと矢印を表示せず、状態がないことを案内し、以前の図を残さない。

#### Scenario: REQ-014-S01 - 2表の間に名前と指定色を持つノードを表示する

- **GIVEN** 状態`Z_IDLE`(待機、`#4F46E5`)、`A_RUN`(実行中、`#22C55E`)を定義している。
- **WHEN** プレビューを開く。
- **THEN** 上から状態定義表、状態遷移図、状態遷移表の順で表示される。
- **AND** 図には`待機`と`実行中`のノードが各1件あり、それぞれのノードに対応する指定カラーが使われ、名前の代わりにIDは表示されない。

#### Scenario: REQ-014-S02 - 同じ名前でも状態IDを区別する

- **GIVEN** 異なるIDの状態2件の名前がともに`待機`で、それぞれから異なる状態への遷移がある。
- **WHEN** 図を表示する。
- **THEN** `待機`のノードは2件あり、それぞれの矢印は遷移元IDに対応するノードから出て、名前によって1件へ統合されない。

#### Scenario: REQ-014-S03 - イベントや遷移のない状態も表示する

- **GIVEN** 状態2件があり、次のいずれかの内容である。

  | 内容 | 期待する図 |
  | --- | --- |
  | イベントも遷移もない | 状態ノード2件、矢印0本 |
  | イベントがあり遷移がない | 状態ノード2件、矢印0本 |
  | 1件の状態だけに自己遷移がある | 状態ノード2件、自己ループ1本 |

- **WHEN** 図を表示する。
- **THEN** 図は表の結果となり、遷移のない状態が欠落しない。

#### Scenario: REQ-014-S04 - 状態がなくなったら古い図を消す

- **GIVEN** ノードと矢印を持つ図を表示している。
- **WHEN** 文書を空にする、またはイベントだけの有効な内容へ変更する。
- **THEN** 図領域には状態がないことの案内があり、ノードと矢印は0件で、以前の状態名は残らない。

#### Scenario: REQ-014-S05 - 状態名を文字列として表示する

- **GIVEN** 状態名に`<script>window.glsDiagramExecuted = true</script>`を持つ状態と、`<b>待機</b>`を持つ状態がある。
- **WHEN** 図を表示する。
- **THEN** 両方の名前の文字列がそのまま表示され、図内に`script`要素や`b`要素は生成されず、`window.glsDiagramExecuted`は設定されない。

### Requirement: REQ-015 - 状態間の方向付き矢印

WHEN 状態遷移図を表示するとき、図は、分岐なし遷移とREQ-026の各分岐が持つ遷移先状態IDを遷移元ノードから遷移先ノードへの矢印として表示しなければならない(SHALL)。\
処理の有無によらず遷移先で矢印の有無を決め、遷移なしと未定義の組み合わせには矢印を作らない。\
同じ遷移元IDと遷移先IDの組み合わせはイベントが異なっても1本にまとめ、逆方向は別の矢印とする。\
自状態への遷移は外側へ張り出して同じノードへ戻る自己ループとし、相互の矢印は方向を区別できる経路にする。\
イベント名、条件名と処理のラベルは表示しない。\
REQ-031の集約対象だけは遷移元ノードの代わりにグループ枠を始点とし、到達先は個々の状態ノードのままにする。

#### Scenario: REQ-015-S01 - 遷移先へ向く矢印をラベルなしで表示する

- **GIVEN** 状態`IDLE`と`RUNNING`があり、イベント`START`(開始要求)に対して`IDLE`から`RUNNING`へ処理`開始を記録する`を定義している。
- **WHEN** 図を表示する。
- **THEN** 矢印は1本で、始点は`IDLE`のノード、終点の矢尻は`RUNNING`のノードにある。
- **AND** 図には`開始要求`、`START`、`開始を記録する`のラベルがない。

#### Scenario: REQ-015-S02 - 遷移なしと未定義を矢印へ変換しない

- **GIVEN** 状態`IDLE`、`RUNNING`とイベント`START`があり、対象の組み合わせは次のいずれかである。

  | 定義 | 期待する矢印 |
  | --- | --- |
  | 処理なし、遷移先RUNNING | IDLEからRUNNINGへの1本 |
  | 処理あり、遷移なし | 0本 |
  | 処理なし、遷移なし | 0本 |
  | 定義がない | 0本 |

- **WHEN** 図を表示する。
- **THEN** 矢印は表の結果となり、遷移なしや未定義から自己ループは作られない。

#### Scenario: REQ-015-S03 - 同じ向きの状態間の関係をまとめる

- **GIVEN** 異なるイベント`START`、`RETRY`でともに`IDLE`から`RUNNING`へ遷移し、処理は異なっている。
- **WHEN** 図を表示する。
- **THEN** `IDLE`から`RUNNING`への矢印は1本だけで、イベントや処理の違いによって重複しない。
- **AND** 状態遷移表では各イベントの処理と遷移先が別々のセルに保持される。

#### Scenario: REQ-015-S04 - 自状態への遷移を自己ループで示す

- **GIVEN** 異なるイベント2件でともに`IDLE`から`IDLE`へ遷移している。
- **WHEN** 図を表示する。
- **THEN** `IDLE`から出てノード外側を通り、矢尻が`IDLE`へ戻る自己ループが1本あり、長さ0の線や別の状態への矢印にはならない。

#### Scenario: REQ-015-S05 - 相互の遷移を区別する

- **GIVEN** `IDLE`から`RUNNING`と、`RUNNING`から`IDLE`の遷移がある。
- **WHEN** 図を表示する。
- **THEN** 矢印は2本あり、それぞれの終点に矢尻があり、経路が完全には重ならず、両方向の存在を確認できる。

### Requirement: REQ-016 - 状態を主役にした図の配色

WHEN 状態遷移図を表示するとき、図は、矢印の線と矢尻を淡い色でそろえ、VS Codeの明暗テーマに追従する背景上で、状態名、指定カラー、矢印の方向を読み取れるようにしなければならない(SHALL)。\
矢印を状態カラーやイベントごとの強い色で塗り分けない。

#### Scenario: REQ-016-S01 - 矢印の線と矢尻に共通の淡い配色を使う

- **GIVEN** 異なる指定カラーを持つ状態間の矢印と自己ループがある。
- **WHEN** 図を表示する。
- **THEN** 通常の矢印と自己ループの線と矢尻は共通の淡い配色であり、状態の指定カラーを矢印へ転用しない。

#### Scenario: REQ-016-S02 - 明暗テーマで状態と方向を確認できる

- **GIVEN** 指定カラー付きの状態ノードと通常の矢印、自己ループを含む図を表示している。
- **WHEN** VS CodeのDark+とLight+を切り替える。
- **THEN** 図の背景と基本の文字色はテーマに追従し、状態名と淡い矢印の方向を読み取れ、状態の指定カラーは保たれる。

### Requirement: REQ-017 - 3表示を同じ現在の文書へ追従させる

WHEN プレビュー対象の内容が変わるとき、プレビューは、REQ-003、REQ-005、REQ-006、REQ-013の対象文書、保存前の更新、古い結果の拒否、診断と正常表示の保持を状態遷移図にも適用し、両方の表と図を同じ正常な内容から表示しなければならない(SHALL)。\
正常な内容がない文書では他の文書の図を表示しない。\
修正後は3表示を現在の内容へ更新し、診断とエラー案内を消す。\
同じURIを小さい版番号で開き直しても自動更新とコマンド再実行を受け付け、表示準備中の編集は準備完了時に反映する。

#### Scenario: REQ-017-S01 - 未保存の変更を図と両方の表へ反映する

- **GIVEN** 同じ文書の状態定義表、図、状態遷移表を表示し、保存は行わない。
- **WHEN** 次のいずれかの編集を行う。

  | 編集 | 図の期待する結果 |
  | --- | --- |
  | 状態名とカラーを変更する | 対象ノードの名前とカラーが変わる |
  | 参照されていない状態を追加、削除する | 対象ノードが増減する |
  | 遷移先を別の有効な状態IDへ変更する | 元の矢印が消え、新しい遷移先へ向く |
  | 遷移先をなしにする | 対象の状態間の矢印が消える |
  | 同じ向きの最後の遷移を削除する | 対象の矢印が消える |
  | 同じ向きの複数の遷移のうち1件だけを削除する | 対象の矢印は1本のまま残る |
  | 遷移なしから自状態への遷移へ変更する | 自己ループが1本現れる |
  | イベント名や処理だけを変更する | ノードと矢印の関係は変わらない |

- **THEN** 手動更新なしで図は表の結果となり、両方の表も同じ編集後の定義に従い、文書は未保存のままである。

#### Scenario: REQ-017-S02 - 参照エラーで3表示を保つ

- **GIVEN** 正常な3表示を表示している。
- **WHEN** 遷移先を未宣言の`MISSING`へ変更する。
- **THEN** Problemsには遷移宣言行を指す参照エラーがあり、図と両方の表は直前の正常な名前、カラー、処理、矢印と遷移先を保つ。

#### Scenario: REQ-017-S03 - 保持した正常表示から修正後の3表示へ回復する

- **GIVEN** 正常な3表示の後に参照エラーとなり、診断とエラー案内があり、3表示は直前の正常な内容を保持している。
- **WHEN** 保存せず、状態名と処理を以前とは異なる内容にし、遷移先を以前と異なる有効な状態IDへ修正する。
- **THEN** 図の状態名と矢印の終点、両方の表の状態名、処理、遷移先は修正後の内容で一致し、以前の正常な内容には戻らない。
- **AND** 診断とエラー案内は消え、文書は未保存のままである。

#### Scenario: REQ-017-S04 - 不正な別文書へ切り替えたら以前の図を表示しない

- **GIVEN** 正常なA.glsの3表示を表示し、B.glsには未宣言IDへの参照があり、一度も正常に表示していない。
- **WHEN** B.glsからプレビューコマンドを実行する。
- **THEN** B.glsの参照診断と表示できないことの案内があり、A.glsのノード、矢印と両方の表のデータは残らない。

#### Scenario: REQ-017-S05 - 遅れた古い解析結果と通知を使わない

- **GIVEN** 最新の状態名、処理と遷移先を反映した3表示と診断がある。
- **WHEN** 古い内容の解析結果、表示通知または図の表示準備完了が遅れて届く。
- **THEN** 3表示と診断は最新のままで、古い状態名、矢印、処理、遷移先、エラーへ戻らない。

#### Scenario: REQ-017-S06 - 小さい版番号で再オープンしても更新する

- **GIVEN** プレビューを残して文書を閉じ、同じURIを閉じる前より小さい版番号で開き直している。
- **WHEN** 次のいずれかの操作を行う。

  | 操作 | 期待する結果 |
  | --- | --- |
  | コマンドを再実行せず状態名と遷移先を未保存で変更する | 同じプレビューの3表示が編集後の内容になる |
  | 再オープンした文書からコマンドを実行する | 既存の単一プレビューの3表示が現在の内容になる |

- **THEN** 閉じる前より小さい版番号のままでも期待する結果となり、閉じる前のノード、矢印と表のデータは残らない。

#### Scenario: REQ-017-S07 - 表示準備中の変更を最初の図へ反映する

- **GIVEN** プレビューの表示準備が完了する前に、状態名`待機`を`準備中の編集`にし、遷移先を別の有効な状態IDへ未保存で変更している。
- **WHEN** 図の表示準備が完了する。
- **THEN** 最初に表示する3表示は`準備中の編集`と変更後の遷移先に対応し、古いノードや矢印を表示するための追加の編集やコマンド再実行は不要である。

#### Scenario: REQ-017-S08 - 別の文書の編集を混入させない

- **GIVEN** A.glsの3表示を表示している。
- **WHEN** 別のB.glsの状態名と遷移先を編集する。
- **THEN** 対象はA.glsのままで、3表示と診断はB.glsの内容に変化しない。

### Requirement: REQ-026 - 各分岐の到達先を状態間の矢印へ反映する

WHEN 分岐付き遷移を図に表示するとき、図は、各分岐の遷移先状態IDを元の状態からの有向ペアへ変換し、REQ-015の矢印として表示しなければならない(SHALL)。\
共通処理と各分岐の処理の有無によらずすべての分岐を対象とし、同じ有向ペアは分岐とイベント、分岐の有無をまたいで1本へまとめる。\
REQ-031のグループ集約条件を満たす有向ペアだけは枠から到達先への1本にまとめ、個々の分岐定義は維持する。\
遷移なしから矢印を作らず、自己遷移と逆方向はREQ-015に従う。\
状態ノードの名前とカラー、淡い矢印と矢尻を保ち、条件名、イベント名、共通処理と分岐の処理のラベル、条件用ノードは追加しない。

#### Scenario: REQ-026-S01 - すべての分岐の異なる遷移先へ矢印を作る

- **GIVEN** `IDLE`から`START`で、共通処理と、`準備完了`(開始する、RUNNING)、`異常`(処理なし、FAILED)の2分岐を定義している。
- **WHEN** 図を表示する。
- **THEN** `IDLE`から`RUNNING`と`IDLE`から`FAILED`への矢印がそれぞれ1本あり、矢尻は各終点へ向き、2つ目の分岐や処理なしの分岐も省略されない。
- **AND** 状態ノードだけが存在し、状態名とカラーを保ち、共通処理、条件名、イベント名と分岐の処理のラベルはない。

#### Scenario: REQ-026-S02 - 分岐と既存遷移の同じ有向ペアを集約する

- **GIVEN** `START`の異なる条件2件と、分岐なしの`RETRY`がすべて`IDLE`から`RUNNING`へ遷移する。
- **WHEN** 図を表示する。
- **THEN** `IDLE`から`RUNNING`への矢印は1本だけで、表には元の2分岐と分岐なしセルの処理が別々に残る。

#### Scenario: REQ-026-S03 - 分岐でも遷移なし、自己遷移と逆方向を区別する

- **GIVEN** 次のいずれかの遷移を定義している。

  | 定義 | 期待する矢印 |
  | --- | --- |
  | IDLEの分岐の遷移先がすべて`-` | 0本 |
  | IDLEの分岐の遷移先がIDLEと`-` | IDLEの外側を通ってIDLEへ戻る自己ループ1本 |
  | IDLEの分岐がRUNNINGへ、分岐なし遷移がRUNNINGからIDLEへ | 完全には重ならない両方向の2本 |

- **WHEN** 図を表示する。
- **THEN** 表の結果だけがあり、自己ループや通常の矢印、相互遷移の各矢尻がそれぞれの経路終端の進行方向と一致し、遷移なしから自己ループは作られない。

### Requirement: REQ-030 - 所属状態を囲む名前付きの実線枠

WHEN 有効な状態グループをプレビューするとき、状態遷移図は、グループ名を持つ実線の枠で所属する状態ノードだけを囲み、個々の状態名と指定カラーを保持しなければならない(SHALL)。\
同名の状態とグループはIDで区別し、未所属状態はどの枠にも含めず、各グループと未所属状態の領域を重ねない。\
所属状態は状態の定義順に配置し、枠内に名前と状態、内部の自己ループを欠落なく収め、グループ名は表示用テキストとして扱う。\
状態定義表と状態遷移表の間という配置とテーマに沿う表示を保ち、グループ宣言がなければ既存の図を維持する。\
表示範囲はREQ-040、状態定義表からの状態選択の表示はREQ-036に従い、図からの状態選択とグループ選択は追加せず、操作部はREQ-038の縮小、Reset、拡大だけとする。

#### Scenario: REQ-030-S01 - 指定した状態だけを実線の枠で囲む

- **GIVEN** 定義順が`A`、未所属`X`、`B`、`C`の状態があり、グループ`G`(稼働系)の所属は`C`、`A`、`B`の順で指定している。
- **WHEN** 図を表示する。
- **THEN** `稼働系`の実線枠は1つで、内部の状態は定義順の`A`、`B`、`C`の各1件であり、それぞれの名前と指定カラーが保たれる。
- **AND** `X`は枠外にあり、枠は状態定義表と状態遷移表の間にだけ表示される。

#### Scenario: REQ-030-S02 - 同名グループと名前の文字列を区別する

- **GIVEN** 異なるIDのグループ2件が同じ名前`<b>稼働系</b>`で、それぞれの所属状態は異なり、同名状態もある。
- **WHEN** 図を表示する。
- **THEN** 同名グループの実線枠は2つで重ならず、状態の統合と混入はなく、グループ名の文字列は各枠にそのまま表示され、b要素は作られない。

#### Scenario: REQ-030-S03 - 長い名前と実測した状態とループを枠に収める

- **GIVEN** 折り返しが必要な長いグループ名と複数行の状態名、上へ張り出す自己ループを持つグループと、別グループと未所属状態がある。
- **WHEN** 初回に図の配置が完了する。
- **THEN** グループ名の末尾、所属状態の全領域と自己ループの経路が枠内に収まり、名前と状態は重ならず、別グループと未所属状態は枠外である。
- **AND** 枠とノード、矢印は図領域内へ収まり、長い内容を省略せず、状態定義表からの選択表示を除き、図からの状態選択とグループ選択はなく、操作ボタンはREQ-038の縮小、Reset、拡大だけである。

#### Scenario: REQ-030-S04 - グループの除去で従来の図へ戻す

- **GIVEN** グループ枠と所属状態を表示している。
- **WHEN** 有効なままグループ宣言だけをすべて除去する。
- **THEN** 枠とグループ名は残らず、全状態の名前とカラー、定義順の配置は同じ内容のグループなし文書と一致する。

### Requirement: REQ-031 - 複数の所属状態から同一外部状態への矢印集約

WHEN 図の矢印を表示するとき、状態遷移図は、同じグループの異なる2状態以上から同じグループ外の状態へ向く遷移を、グループ枠からその状態へ向く1本に集約しなければならない(SHALL)。\
グループと到達先ごとに、イベントと分岐、処理の有無によらず異なる遷移元状態を数え、全メンバーの一致を要求しない。\
集約した個別矢印は残さず、1状態だけからの遷移、グループ内への遷移、自己遷移はREQ-015とREQ-026に従い、遷移なしは矢印を作らない。\
1状態から複数状態への矢印はまとめず、到達先が別グループに所属していても終点は個々の状態とする。\
淡い線と矢尻、ラベルなしを保ち、すべての矢尻を経路終端の進行方向へ向ける。

#### Scenario: REQ-031-S01 - 一部のメンバーだけの共通到達先も枠から1本にする

- **GIVEN** グループ`G`に`A`、`B`、`C`が所属し、`A`と`B`から外部状態`X`へ遷移し、`C`にはXへの遷移がない。
- **WHEN** 図を表示する。
- **THEN** `G`の実線枠の境界を始点、`X`の状態ノードを矢尻の終点とする矢印が1本あり、AからXとBからXの個別矢印はない。
- **AND** CからXの遷移定義は作られず、イベント名、条件名と処理のラベルはない。

#### Scenario: REQ-031-S02 - イベントと分岐をまたいで異なる遷移元を数える

- **GIVEN** GにAとBが所属し、AはSTARTの分岐なし遷移でXへ、BはRETRYの2番目の分岐で処理なしでXへ向かい、ほかの分岐はYへ向かう。
- **WHEN** 図を表示する。
- **THEN** GからXへ1本、BからYへ1本があり、2番目の分岐と処理なしの遷移を省略せず、元のAからXとBからXの矢印を重ねない。

#### Scenario: REQ-031-S03 - 同じ1状態の重複遷移では枠を始点にしない

- **GIVEN** GにAとBが所属し、Aだけが異なるイベントと複数の分岐でXへ遷移し、BからXの遷移はない。
- **WHEN** 図を表示する。
- **THEN** AからXへの矢印だけが1本あり、遷移定義の件数によってGからXへの矢印を作らない。

#### Scenario: REQ-031-S04 - 内部遷移と自己遷移となしを集約しない

- **GIVEN** GにA、B、Cが所属し、AからC、BからC、AからA、Bから遷移なしがある。
- **WHEN** 図を表示する。
- **THEN** AからCとBからCの各1本、Aの外側からAへ戻る自己ループ1本だけがあり、GからCやGからGの矢印と、なしからの矢印はない。

#### Scenario: REQ-031-S05 - 到達先と遷移元グループを混同せず逆向きの集約をしない

- **GIVEN** GはA、B、Cを持ち、HはX、Yを持ち、AとBからX、AだけからY、未所属UからXとY、別グループJの2状態からXへ遷移している。
- **WHEN** 図を表示する。
- **THEN** Gから状態X、状態Aから状態Y、状態Uから状態Xと状態Y、Jから状態Xへの5本だけがある。
- **AND** Hの枠を終点とする矢印や、GとJを1つの始点へまとめた矢印はなく、Xへの集約に無関係なGのCからの遷移は作られない。

#### Scenario: REQ-031-S06 - 集約された往路と個別の復路の方向を保つ

- **GIVEN** GのAとBから外部Xへ向かう遷移と、XからAへ戻る遷移がある。
- **WHEN** 図を表示する。
- **THEN** Gの枠からXへ向かう1本と、XからAへ戻る1本があり、経路は完全には重ならず、それぞれの矢尻の向きは経路終端の進行方向と一致する。
- **AND** グループ内の自己ループと通常の個別矢印も、それぞれの状態を終点として矢尻の向きを保つ。

### Requirement: REQ-033 - 編集中のグループと3表示の整合

WHEN 対象文書のグループまたは所属状態に関係する定義を編集するとき、プレビューは、REQ-017とREQ-027の更新と診断の規則をグループにも適用し、保存前の同じ内容へ枠と矢印、両表を追従させなければならない(SHALL)。\
グループの追加と除去、名前と所属、個々の遷移先の変更で枠と集約を再判定する。\
誤りでは同じURIの正常な3表示を保持し、修正後は現在の異なる内容へ回復して診断と案内を消す。\
古い通知と不正なグループモデル、別文書を混入させず、小さい版番号での再オープンと図の準備中の変更でも、現在の枠と矢印と両表がそろってから現在の描画完了だけを通知する。

#### Scenario: REQ-033-S01 - 所属と遷移を未保存で変更して枠と集約を更新する

- **GIVEN** 分類と条件分岐を持ち、GのAとBから外部Xへ向かう正常な3表示を開いている。
- **WHEN** 次のいずれかの編集を保存せずに行う。

  | 編集 | 期待する図 |
  | --- | --- |
  | グループの追加または除去 | 指定した枠と名前だけが増減し、個別と集約の矢印が切り替わる |
  | グループ名だけを変更 | 名前だけが変わり、所属と到達先は不変 |
  | BをGから別グループへ移す | 枠の所属が変わり、Xへの遷移元が1状態の各グループでは個別矢印となる |
  | BからXを別状態またはなしへ変更 | Xへの集約は解除され、残る個別矢印と現在の到達先だけを表示 |
  | 別メンバーからXへの遷移を追加 | GからXへの1本に戻る |

- **THEN** 手動更新なしで表の結果となり、両表は個々の現在の状態と遷移、分類と分岐を保ち、文書は未保存のままである。

#### Scenario: REQ-033-S02 - 所属エラーで保持して異なる現在の内容へ回復する

- **GIVEN** G(稼働系)はAとBを囲みXへ集約し、分類と共通処理と分岐、状態名を持つ正常な3表示がある。
- **AND** Gの所属をMISSINGへ変えており、所属行の参照診断とエラー案内があり、直前の正常な3表示を保持している。
- **WHEN** 保存せず、名前を復旧系、所属をBとC、到達先を別状態Y、状態名と共通処理と条件と処理、分類と列見出しを以前と異なる有効な内容へ修正する。
- **THEN** 復旧系の枠はBとCだけを囲み、Yへの集約矢印と個別の遷移を含む両表の全変更が現在の内容となり、診断と案内は消え、文書は未保存のままである。

#### Scenario: REQ-033-S03 - 古い通知と不正なグループモデルを受理しない

- **GIVEN** 最新のグループと個別遷移を持つ正常な3表示がある。
- **WHEN** 古い通知順の有効なモデル、または新しい通知順で次の1項目だけが不正な通知が届く。

  | 項目 | 不正な内容 |
  | --- | --- |
  | グループ一覧 | 配列以外、null |
  | グループIDと名前 | 欠落、型違い、不正なID、空白だけや引用符と改行を含む名前、IDの重複 |
  | 所属状態 | 欠落、配列以外、null、2件未満、文字列以外、不正なID、未宣言の状態、同じグループ内の重複、複数グループへの重複所属 |
  | グループの要素 | 余分な入れ子や状態と遷移を埋め込んだ項目 |

- **THEN** 現在の枠と実矢印、両表と診断を保ち、グループを読み飛ばして新しい表示へ進んだり、不正な通知の描画完了を送ったりしない。

#### Scenario: REQ-033-S04 - 小さい版番号の再オープン後もグループを更新する

- **GIVEN** 単一プレビューを残して文書を閉じ、同じURIを閉じる前より小さい版番号で開き直している。
- **WHEN** コマンドを再実行せずグループと遷移を未保存で変更する、または再オープンした文書からプレビューコマンドを再実行する。
- **THEN** 両操作とも同じ単一プレビューの枠と集約矢印、両表が現在の異なる内容となり、閉じる前の所属と矢印は残らない。

#### Scenario: REQ-033-S05 - 別文書のグループと正常表示を混ぜない

- **GIVEN** A.glsの正常なグループ付き3表示があり、B.glsには正常履歴がなくグループの参照エラーがある。
- **WHEN** B.glsを編集するだけ、またはB.glsからプレビューコマンドを実行する。
- **THEN** 編集だけなら対象と3表示と診断はAのままであり、コマンドならBの所属行の診断と表示できない案内になり、Aの枠と矢印、両表は残らない。

#### Scenario: REQ-033-S06 - 枠の計測中の変更を現在の描画完了に反映する

- **GIVEN** グループ名と所属状態の計測が終わる前に、グループ名、所属、共通処理と到達先を変更している。
- **WHEN** 現在の枠と矢印の配置が完了する、または以前の配置の完了が遅れて届く。
- **THEN** 最初の完了通知時点で現在の名前と所属だけを囲む枠、境界から現在の到達先への非零長の矢印、両表がそろい、現在のURIと版番号と通知順に対応する完了だけを送り、古い枠と矢印へ戻らない。

### Requirement: REQ-036 - 選択した状態ノードだけの背景強調

WHILE REQ-034の状態選択がある間、状態遷移図は、選択した状態IDのノードだけを薄い背景色で強調しなければならない(SHALL)。\
同名の別状態と所属グループ全体、他のメンバー、入出力矢印と接続先ノードへ強調を広げず、グループIDと状態IDが同じ場合も状態だけを対象とする。\
指定カラーの状態名と、REQ-031の集約と自己ループ、淡い矢印とその向きを保ち、選択を示す枠線を追加しない。\
図からの選択切替、選択に伴う配置変更、自動ズームと自動スクロールは行わず、解除したらそのノードを通常の背景へ戻す。

#### Scenario: REQ-036-S01 - 同名状態と接続関係へ強調を広げない

- **GIVEN** AとBは同名の別状態で、AからC、BからA、AからAの遷移がある。
- **WHEN** 状態定義表でAを選択する。
- **THEN** Aのノード1件だけの背景が変わり、BとCの背景、すべての矢印と矢尻の配色と向きは選択前と一致する。
- **AND** Aの名前の指定カラーと矢印の本数と終点は変わらず、Aを解除したら背景が選択前へ戻る。

#### Scenario: REQ-036-S02 - グループ所属と同一IDの枠を区別する

- **GIVEN** グループIDがAで、所属状態はAとBであり、両状態から外部Xへの矢印は枠から1本へ集約されている。
- **WHEN** 状態定義表で状態Aを選択する。
- **THEN** Aの状態ノードだけの背景が変わり、Aのグループ枠と名前、BとX、集約矢印の表示は選択前と一致する。
- **AND** 図のBやグループ枠をクリックしても選択状態はAのままであり、グループを選択したことにはならない。

#### Scenario: REQ-036-S03 - 選択で図の配置と表示範囲を変えない

- **GIVEN** 状態ノードとグループ枠、自己ループを表示した図の配置が完了している。
- **WHEN** 状態定義表で状態を選択、切替、解除する。
- **THEN** ノードと枠の位置と寸法、矢印の経路、図の拡大率と表示位置は操作前と一致し、対象状態への自動移動はない。

### Requirement: REQ-038 - 状態遷移図の倍率操作部

WHEN 状態遷移図を表示するとき、プレビューは、図の上部に左から`-`、`Reset`、`+`の3ボタンと現在の倍率の%表示を設け、縮小、等倍、拡大として判別可能にしなければならない(SHALL)。\
拡大と縮小は現在の表示中心を維持し、設定した刻みと上下限に従って図だけの倍率を変える。\
マウスとTab、Enter、Spaceによる操作を受け付け、キーボードフォーカスを示し、明暗テーマで操作内容を読めるようにする。\
既存のドラッグとホイール操作を保ち、倍率表示は実際の図の倍率に追従する。\
図の準備前は操作部からの倍率操作を受け付けず、図がない場合は操作部を表示しない。\
状態と遷移の内容と配置、両表、選択状態を変えず、画像保存と図からの選択操作を追加しない。

#### Scenario: REQ-038-S01 - 3操作と実際の倍率を表示する

- **GIVEN** グループと自己ループを持つ図を表示している。
- **WHEN** 図の操作部を確認する。
- **THEN** 図の上部のボタンの表示文字は左から`-`、`Reset`、`+`で、読み上げ用の名前は`縮小`、`等倍`、`拡大`である。
- **AND** 実際の図の倍率を%で示し、画像保存や状態とグループの選択の操作ボタンはない。

#### Scenario: REQ-038-S02 - 表示中心を維持して図だけを拡大縮小する

- **GIVEN** 上下限から離れた倍率で図を移動し、状態Aを選択している。
- **WHEN** 次のいずれかのボタンを押す。

  | ボタン | 期待する倍率 |
  | --- | --- |
  | + | 設定した刻みだけ増加 |
  | - | 設定した刻みだけ減少 |

- **THEN** 倍率は表の結果となり、表示領域の中心に対応する図上の位置は操作前と一致する。
- **AND** 図上のノードと枠の配置、遷移先と矢尻の方向、両表の内容と大きさ、Aの選択は変わらない。

#### Scenario: REQ-038-S03 - 設定した倍率の境界を超えない

- **GIVEN** 倍率が設定した上限または下限に近い図がある。
- **WHEN** 上限に向けて拡大を繰り返す、または下限に向けて縮小を繰り返す。
- **THEN** ボタンと既存のホイールのいずれでも倍率は設定した範囲内にあり、倍率表示は実際の倍率に対応し続ける。

#### Scenario: REQ-038-S04 - キーボードで3操作を起動する

- **GIVEN** 図の3ボタンへTabで到達できる。
- **WHEN** 縮小、等倍、拡大のいずれかにフォーカスを移し、EnterまたはSpaceで起動する。
- **THEN** フォーカスだけでは倍率を変えず、起動1回につき対応する倍率操作を1回行い、フォーカス位置を読み取れる。

#### Scenario: REQ-038-S05 - 既存の移動とホイールに倍率表示を追従させる

- **GIVEN** 図と操作部を表示している。
- **WHEN** 図をドラッグする、またはホイールで倍率を変える。
- **THEN** ドラッグでは表示位置だけが変わり、ホイールでは実際の倍率と%表示がそろって変わり、操作部のクリックをドラッグとして扱わない。

#### Scenario: REQ-038-S06 - 図がない場合は操作部を表示しない

- **GIVEN** 状態0件の有効な文書、または一度も正常に表示していない解析エラーの文書である。
- **WHEN** プレビューを表示する。
- **THEN** 既存の不足または解析エラーの案内を表示し、図の倍率操作部と倍率表示はない。

#### Scenario: REQ-038-S07 - 計測中の倍率操作を受け付けない

- **GIVEN** 図の状態名とグループ枠の計測が完了していない。
- **WHEN** 倍率のボタンを起動しようとする。
- **THEN** 倍率操作は行われず、準備完了後に現在の図を操作できる。

#### Scenario: REQ-038-S08 - 明暗テーマで操作とフォーカスを読み取る

- **GIVEN** 図と操作部を表示している。
- **WHEN** 明テーマまたは暗テーマでボタンへフォーカスを移す。
- **THEN** 操作部の文字と背景、フォーカス表示はテーマに沿い、3操作と倍率を読み取れ、図の指定カラーと淡い矢印は保たれる。

### Requirement: REQ-039 - 表示中心を維持する等倍Reset

WHEN 利用者が状態遷移図のResetを起動するとき、プレビューは、現在の表示領域の中心に対応する図上の位置を維持したまま、倍率を100%へ戻さなければならない(SHALL)。\
図全体を収める操作や初回の表示位置への復帰として扱わず、すでに100%なら表示位置も倍率も変えない。

#### Scenario: REQ-039-S01 - 等倍へ戻して現在の中心を保つ

- **GIVEN** 等倍では表示領域に収まらない図を、100%未満または100%より大きい倍率で初回とは異なる位置へ移動している。
- **WHEN** Resetを起動する。
- **THEN** 図の実際の倍率と倍率表示は100%になり、表示領域の中心に対応する図上の位置は操作前と一致する。
- **AND** 図全体へ自動で縮小せず、初回の中心へ移動しない。

#### Scenario: REQ-039-S02 - すでに等倍なら移動しない

- **GIVEN** 図の倍率は100%で、表示位置は初回から移動している。
- **WHEN** Resetを起動する。
- **THEN** 倍率は100%のままで表示位置は変わらず、図を初回の位置や全体表示へ戻さない。

### Requirement: REQ-040 - 対象文書ごとの表示範囲の継続

WHEN プレビューの対象内容が更新されるとき、状態遷移図は、同一文書で確定した倍率と表示位置を、配置が変わるDSL編集と解析エラーによる正常表示の保持でも維持しなければならない(SHALL)。\
初回に図を表示できるときと対象文書の切替時、図の表示領域のサイズ変更時は、現在の図全体を収める。\
同一文書の状態0件の間も直前の表示範囲を記憶し、状態の再追加、小さい版番号での再オープン、コマンド再実行で初期化しない。\
文書別の履歴と新しいプレビューへの復元は行わず、別文書へ切り替えてから戻った場合も全体表示から始める。\
古い通知、不正な通知と遅れた表示準備の完了は現在の表示範囲を変えず、受理した現在の内容の配置と表示範囲が確定してから既存の描画完了を通知する。\
倍率や位置、Resetと状態選択の操作だけではDSL、診断と描画完了通知を変更しない。

#### Scenario: REQ-040-S01 - 初めて表示できる図を全体へ収める

- **GIVEN** 新しいプレビューに初めて図を表示する、または状態0件や正常表示のない文書に初めて有効な状態を定義する。
- **WHEN** 現在の図の準備が完了する。
- **THEN** 現在の全状態ノードとグループ枠、自己ループと矢印を表示領域へ収め、初期の倍率表示も実際の倍率と一致する。

#### Scenario: REQ-040-S02 - 同一文書の内容と配置の変更で表示範囲を保持する

- **GIVEN** 図を手動で拡大して移動し、状態Aを選択している。
- **WHEN** 次のいずれかを有効なまま保存前に編集する。

  | 編集 | 期待する表示内容 |
  | --- | --- |
  | 状態名、意味、カラー | 現在の状態名、意味、カラー |
  | 状態の追加、選択中以外の削除、定義順の変更 | 現在の状態数と定義順による配置 |
  | グループ名、所属の変更とグループの追加、除去 | 現在の枠と所属による配置 |
  | 分類と列見出し、処理と分岐の条件 | 現在の分類とセル |
  | 遷移先と分岐の追加、除去 | 現在の矢印と各交点 |

- **THEN** 3表示の内容は現在の定義となり、図の倍率と表示位置は編集前と一致し、全体表示へ戻らない。
- **AND** Aの選択はREQ-035に従い、新たな状態が表示領域外でも自動で移動しない。

#### Scenario: REQ-040-S03 - エラー中の操作と異なる内容への修正で保持する

- **GIVEN** 拡大して移動した正常な3表示の後に遷移先の参照エラーとなり、診断と案内を表示して直前の正常な図を保持している。
- **AND** エラー中にさらに倍率と位置を変えている。
- **WHEN** 状態名と処理と遷移先を以前とは異なる有効な内容へ修正する。
- **THEN** 3表示はすべて現在の異なる内容となり、診断と案内は消え、図はエラー中の最後の操作後の倍率と表示位置を保つ。

#### Scenario: REQ-040-S04 - 状態0件を経由しても同一文書の表示範囲を保持する

- **GIVEN** 初回の全体表示から倍率と位置を変えた文書の状態を0件にし、図の操作部はない。
- **WHEN** 同じ文書に有効な状態を再追加する。
- **THEN** 現在の状態だけを表示し、直前の図の倍率と位置を復元し、初回の全体表示へ戻らない。

#### Scenario: REQ-040-S05 - 同じ図でも別文書では全体表示から始める

- **GIVEN** A.glsの倍率と表示位置を操作し、B.glsはAと同じ図、異なる図、または正常表示がない文書である。
- **WHEN** B.glsからプレビューコマンドを実行する。
- **THEN** 正常な図ならBの図全体を収め、正常表示がなければBの案内だけを表示し、Aの表示範囲を適用しない。
- **AND** Aへ戻っても以前の操作後の範囲は復元せず、現在のAの図全体を収める。

#### Scenario: REQ-040-S06 - 小さい版番号とコマンド再実行で保持する

- **GIVEN** プレビューを残し、倍率と位置を操作した同じURIを閉じる前より小さい版番号で開き直している。
- **WHEN** 保存前に状態名と遷移先を変更する、または同じ文書からプレビューコマンドを再実行する。
- **THEN** 現在の3表示へ更新し、図の倍率と表示位置は最後の操作後のままで、版番号や再実行を理由に全体表示へ戻らない。

#### Scenario: REQ-040-S07 - 拒否する通知と遅れた準備で表示範囲を上書きしない

- **GIVEN** 現在の文書の倍率と位置を操作しており、新しい内容へ更新中である。
- **WHEN** 古い通知順のモデル、新しい通知順でも形式が不正なモデル、または以前の文書や内容の表示準備の完了が遅れて届く。
- **THEN** 現在の文書と内容、倍率と表示位置を維持し、拒否した通知や古い準備完了の描画完了を送らない。
- **AND** 現在の内容の計測が終わったら、その3表示と保持した表示範囲がそろってから現在の描画完了だけを送る。

#### Scenario: REQ-040-S08 - 新しいプレビューでは全体表示から始める

- **GIVEN** 図を拡大して移動したプレビューを閉じている。
- **WHEN** 同じ文書のプレビューを新しく作る。
- **THEN** 現在の図全体を収め、以前の倍率と表示位置を復元しない。

#### Scenario: REQ-040-S09 - 表示操作と状態選択で内容と通知を変更しない

- **GIVEN** 現在の3表示と診断、状態Aの選択がある。
- **WHEN** 拡大、縮小、Reset、図のドラッグ、状態選択の切替または解除を行う。
- **THEN** DSLと診断、図上の配置と矢印、両表の内容と寸法は変わらず、表示操作は選択を変えず、状態選択は表示範囲を変えず、追加の描画完了通知はない。

#### Scenario: REQ-040-S10 - 表示領域のサイズ変更時は全体を収め直す

- **GIVEN** 図の倍率と位置を操作しており、現在の全状態とグループ枠、自己ループと矢印を持つ図がある。
- **WHEN** ウィンドウまたはプレビューの幅や高さを変え、図の表示領域のサイズが変わる。
- **THEN** 現在の図全体を変更後の表示領域へ収め直し、実際の倍率と%表示が一致する。
- **AND** その後の同一文書のDSL編集は、サイズ変更後の倍率と表示位置を保ち、以前の表示範囲へ戻らない。

# state-transitions Specification

## Purpose

開発者が`.gls`で平坦なイベントと状態ごとの処理、遷移先を定義し、状態定義表と状態遷移表で同じ設計を確認できるように、記法、定義順、参照と重複の検証を定める。

## Requirements

### Requirement: REQ-007 - 平坦なイベントの読み取り

WHEN `.gls`を解析するとき、DSL解析機能は、行頭の`Event <ID> as "<イベント名>"`をイベントとして読み取り、IDとイベント名を宣言順に返さなければならない(SHALL)。\
IDの形式とイベント名の引用符、非空の制約はREQ-001のIDと状態名と同じとし、イベントIDは大文字と小文字を区別する。\
異なるIDで同じイベント名を使え、状態IDとイベントIDの名前空間は独立させる。\
イベントを省略した既存の文書や空の文書は有効で、イベントと遷移は0件とする。\
改行形式と空白行はREQ-001に従い、イベント宣言自体の入れ子と本文は設けず、分類経路はREQ-018に従って任意で指定する。

#### Scenario: REQ-007-S01 - 名前とIDを定義順に読み取る

- **GIVEN** 次のイベントを記述している。

  ```gls
  Event Z_START as "開始"
  Event A_STOP as "停止"
  ```

- **WHEN** 内容を解析する。
- **THEN** イベントは`Z_START`(開始)、`A_STOP`(停止)の順の2件であり、IDによる並べ替えや名前の欠落はなく、遷移は0件で、エラーはない。

#### Scenario: REQ-007-S02 - IDと表示名の境界を扱う

- **GIVEN** 状態ID`START`があり、イベントを`START`、`start`、`_START9`の順に、すべてイベント名`開始`で定義している。
- **WHEN** 内容を解析する。
- **THEN** 状態はそのまま保持され、イベントは3件がその順で返り、重複エラーはない。

#### Scenario: REQ-007-S03 - イベントのない既存文書を読み取る

- **GIVEN** 次のいずれかの既存文書がある。

  | 内容 | 期待する状態数 |
  | --- | --- |
  | 有効な状態定義2件のみ | 2 |
  | 空の文書 | 0 |
  | 空白と改行だけの文書 | 0 |

- **WHEN** 内容を解析する。
- **THEN** 状態数は表の値のままで、イベントと遷移はどちらも0件となり、エラーはない。

### Requirement: REQ-008 - 状態とイベントに対応する処理と遷移先の読み取り

WHEN `.gls`を解析するとき、DSL解析機能は、行頭の`Transition <遷移元状態ID> on <イベントID> -> <遷移先>:`と、直後の半角空白4個で始まる処理本文を読み取り、その組み合わせの処理と遷移先を返さなければならない(SHALL)。\
遷移先は状態IDまたは`-`とする。\
IDは宣言済みの状態またはイベントを参照し、宣言の前後関係を問わない。\
処理は1行以上の非空本文を必須とし、インデントと改行の扱いはREQ-001の意味と同じとする。\
本文の非空行が1行で`-`だけなら処理なし、遷移先の`-`は遷移なしを明示し、両方を独立して指定できる。\
処理なしと遷移なしを組み合わせても定義済みであり、遷移なしを遷移元への参照に置き換えない。\
遷移元と同じ状態IDを指定した場合は、その状態への明示的な遷移として保持する。

#### Scenario: REQ-008-S01 - 各参照と処理を読み取る

- **GIVEN** 状態`IDLE`、`RUNNING`、イベント`START`と、次の定義がある。

  ```gls
  Transition IDLE on START -> RUNNING:
      開始を記録する
  ```

- **WHEN** 内容を解析する。
- **THEN** `IDLE`と`START`の組み合わせに処理`開始を記録する`、遷移先`RUNNING`が1件返り、エラーはない。

#### Scenario: REQ-008-S02 - 複数行、空白行と改行形式を扱う

- **GIVEN** 有効な参照を持つ遷移の処理を、半角空白4個で下げた`開始を記録する`と`実行を準備する`の2行で記述している。
- **AND** 次のいずれかの形式で記述している。

  | 改行形式 | 処理の行間の空白だけの行 |
  | --- | --- |
  | LF | あり |
  | CRLF | なし |

- **WHEN** 内容を解析する。
- **THEN** 処理は`開始を記録する`と`実行を準備する`をLFで連結した文字列であり、空白行と先頭のインデントは含まず、エラーはない。

#### Scenario: REQ-008-S03 - 処理なしと遷移なしを独立して保持する

- **GIVEN** 有効な遷移元`IDLE`とイベント`START`に対し、次のいずれかを定義している。

  | 処理本文 | 遷移先 | 期待する結果 |
  | --- | --- | --- |
  | `-` | `RUNNING` | 処理なし、遷移先RUNNINGの定義済み遷移 |
  | `記録する` | `-` | 処理は記録する、遷移なしの定義済み遷移 |
  | `-` | `-` | 処理なし、遷移なしの定義済み遷移 |

- **WHEN** 内容を解析する。
- **THEN** 表の結果どおりに1件が返り、組み合わせが未定義になったり、遷移先が`IDLE`に補われたりせず、エラーはない。

#### Scenario: REQ-008-S04 - 後方の宣言と自状態への参照を解決する

- **GIVEN** 文書の最初に`Transition IDLE on START -> IDLE:`と処理を記述し、その後に状態`IDLE`とイベント`START`を宣言している。
- **WHEN** 文書全体を解析する。
- **THEN** 遷移先は状態`IDLE`への明示的な参照となり、遷移なしには変換されず、エラーはない。

### Requirement: REQ-009 - 不正なイベントと遷移の報告

IF イベントまたは遷移がREQ-007、REQ-008の構文と入力制約を外れる、イベントIDが重複する、状態やイベントの参照先が存在しない、または同じ遷移元状態IDとイベントIDの組み合わせを重複定義する場合、THEN DSL解析機能は、その位置と理由を診断し、文書全体を正常な結果として返してはならない(SHALL)。\
重複は後の宣言行、参照の誤りと必須本文の不足は遷移宣言行、不正な本文インデントは本文行を指す。\
本文に`-`だけの行がある場合は他の非空行を許可せず、2つ目の非空本文行を指す。\
イベント宣言自体の入れ子と条件分岐の構文は受け付けず、平坦な処理本文は表示用テキストとして扱う。

#### Scenario: REQ-009-S01 - 構文と入力制約の誤りを診断する

- **GIVEN** 有効な文書の1か所だけを、次のいずれかに変更している。

  | 不正な箇所 | 入力例 | 診断の対象と理由 |
  | --- | --- | --- |
  | イベントの要素不足 | `Event START` | イベント宣言行、構文 |
  | イベントID | `Event 1START as "開始"` | イベント宣言行、ID |
  | イベント名 | `""`、`"   "` | イベント宣言行、名前 |
  | イベント名の引用符 | 閉じる引用符なし、途中の引用符、引用符内の改行 | イベント宣言行、構文 |
  | 遷移の要素不足 | `on`、`->`、末尾の`:`、遷移先のいずれかを省略 | 遷移宣言行、構文 |
  | 参照IDの形式 | 遷移元、イベント、遷移先のいずれかが`1INVALID` | 遷移宣言行、ID |
  | 処理の不足 | 宣言直後が文書末尾、または空白行だけ | 遷移宣言行、処理 |
  | 処理のインデント | 半角空白2個、8個、タブ1個 | 処理の行、インデント |
  | 処理なしの混在 | 処理本文に`-`と`記録する`の2行 | 2つ目の非空本文行、処理なしの混在 |
  | イベント宣言の入れ子 | イベント宣言の下に半角空白4個で下げた別のイベント宣言 | 子の宣言行、未対応のイベント階層 |
  | 条件分岐 | 遷移本文内に半角空白4個で下げた`If READY:`と8個で下げた処理 | 8個で下げた行、未対応のインデント |

- **WHEN** 内容を解析する。
- **THEN** 表の対象行を指す診断と該当する理由が返り、正常な文書全体の結果は返らない。

#### Scenario: REQ-009-S02 - 参照先がないIDを診断する

- **GIVEN** 有効な遷移の遷移元状態ID、イベントID、遷移先状態IDのうち、1つだけを未宣言の`MISSING`にしている。
- **WHEN** 各内容を解析する。
- **THEN** 遷移宣言行に、未宣言の参照種別と`MISSING`を示す診断が返り、正常な結果は返らない。

#### Scenario: REQ-009-S03 - イベントと組み合わせの重複を診断する

- **GIVEN** 次のいずれかの重複がある。

  | 重複 | 期待する診断 |
  | --- | --- |
  | イベントID`START`を2回宣言する | 2つ目のイベント宣言行にイベントIDの重複 |
  | `IDLE`と`START`の組み合わせを2回定義する | 遷移先や処理が異なっていても、2つ目の遷移宣言行に組み合わせの重複 |

- **WHEN** 各内容を解析する。
- **THEN** 表の位置と理由の診断が返り、後の宣言で上書きした正常な結果は返らない。

### Requirement: REQ-018 - イベントへの任意の分類経路の指定

WHEN `.gls`を解析するとき、DSL解析機能は、既存のイベント宣言の末尾へ任意で付ける`in "<分類名>"`と、` > "<分類名>"`で続けた分類経路を読み取り、各イベントのID、名前、分類の祖先から子への順序を宣言順に返さなければならない(SHALL)。\
分類は1段から3段までとし、イベント名は段数に含めない。\
分類名の引用符、非空、改行とエスケープの制約はREQ-007のイベント名と同じとする。\
キーワードの間は半角空白1個以上、`>`の前後は半角空白0個以上とし、引用符内の文字は空白と`>`も含めて保持する。\
分類を省略した既存イベントを混在でき、分類名は経路全体で所属を区別する。\
イベントIDの一意性と遷移からのID参照は分類に依存せず、宣言の前後関係を問わない。

列見出しは分類経路から独立してREQ-022で宣言し、使う深さまでの見出しを必要とする。

#### Scenario: REQ-018-S01 - 分類のないイベントと1段から3段の分類を読み取る

- **GIVEN** 次のイベントを記述している。

  ```gls
  EventCategoryHeaders "系統" > "区分" > "種別"
  Event Z_FREE as "単独"
  Event Y_START as "開始" in "操作"
  Event X_STOP as "停止" in "操作" > "運転"
  Event W_RETRY as "再試行" in "操作" > "運転" > "復旧"
  ```

- **WHEN** 内容を解析する。
- **THEN** イベントIDは`Z_FREE`、`Y_START`、`X_STOP`、`W_RETRY`の順で、分類経路は順に分類なし、`操作`、`操作 / 運転`、`操作 / 運転 / 復旧`となり、名前も保持され、診断はない。

#### Scenario: REQ-018-S02 - 任意の名前と祖先を含む分類経路を保持する

- **GIVEN** 異なるIDの同名イベント3件を、`業務 / 復旧`、`通信 / 復旧`、`業務 / A > B`へ分類している。
- **AND** 列見出しを`系統`、`区分`の順に宣言している。
- **AND** `A > B`は1組の二重引用符で囲んだ1つの分類名であり、文書はCRLFと空白行を含み、分類キーワードの間には複数の半角空白、分類の区切りの前後には空白のない箇所がある。
- **WHEN** 内容を解析する。
- **THEN** 3件のIDと名前はそのままで、前の2件の分類は祖先を含めて別の経路となり、`A > B`は1つの分類名で、分類順の欠落や余分な段への分割はなく、診断はない。

#### Scenario: REQ-018-S03 - 分類されたイベントを既存のIDで参照する

- **GIVEN** `IDLE`からイベント`START`で`RUNNING`へ遷移し、処理は`開始を記録する`である。
- **AND** 遷移より後に状態と、`操作 / 運転 / 開始系`へ分類した`Event START as "開始"`の宣言がある。
- **AND** 列見出しを`系統`、`区分`、`種別`の順に宣言している。
- **WHEN** 内容を解析する。
- **THEN** 遷移はイベントID`START`を参照し、処理は`開始を記録する`、遷移先は`RUNNING`のままで、分類経路による参照への置き換えや未宣言診断はない。

### Requirement: REQ-019 - 分類経路と列見出しの誤りの報告

IF 分類経路がREQ-018の制約を外れる、列見出しがREQ-022の制約を外れる、または分類が異なっても同じイベントIDを重複宣言する場合、THEN DSL解析機能は、該当する宣言行と理由を診断し、正常な文書全体の結果を返してはならない(SHALL)。\
分類経路の誤りはそのイベント宣言行、重複は後のイベント宣言行を指す。\
列見出しの構文と名前と段数の誤りは見出し宣言行、見出し宣言の重複は後の宣言行、見出し不足は不足する段を最初に使うイベント宣言行を指す。\
誤りを分類なしとして読み飛ばしたり、4段目以降を切り捨てたりしない。

#### Scenario: REQ-019-S01 - 深さと分類構文の誤りを宣言行で診断する

- **GIVEN** 有効な文書のイベント1件を、次のいずれかに変更している。
- **AND** 有効な列見出し3件を宣言している。

  | 不正な箇所 | 末尾の入力例 | 理由 |
  | --- | --- | --- |
  | 深さの超過 | `in "A" > "B" > "C" > "D"` | 分類の上限3段の超過 |
  | 空の分類名 | `in ""`、`in "   "` | 非空の分類名が必要 |
  | 分類の省略 | `in` | 分類経路が必要 |
  | 区切り後の省略 | `in "A" >` | 区切りの後の分類名が必要 |
  | 区切りの省略 | `in "A" "B"` | 分類間の区切りが必要 |
  | 引用符の不正 | 閉じる引用符なし、名前の途中の引用符、引用符内の改行 | 分類名の構文が不正 |

- **WHEN** 内容を解析する。
- **THEN** イベント宣言行に表の理由を識別できる診断があり、正常なモデルは返らず、不正な経路が分類なしや3段までの有効な経路に置き換えられない。

#### Scenario: REQ-019-S02 - 分類が異なってもイベントIDの重複を拒否する

- **GIVEN** イベントID`START`を、次のいずれかの分類の組で2回宣言している。
- **AND** 分類の深さを満たす有効な列見出しを宣言している。

  | 最初 | 後の宣言 |
  | --- | --- |
  | 分類なし | 操作 |
  | 操作 / 開始 | 通信 / 開始 |

- **WHEN** 内容を解析する。
- **THEN** 後の宣言行にイベントID`START`の重複診断があり、正常なモデルは返らず、分類ごとの別IDとしての受理や後の宣言による上書きはない。

#### Scenario: REQ-019-S03 - 不正な列見出しと不足する段を診断する

- **GIVEN** 次のいずれかの誤りがある文書を記述している。

  | 誤り | 入力の例 | 診断の対象と理由 |
  | --- | --- | --- |
  | 見出しなし | 分類が1段で見出し宣言がない | 最初の分類付きイベント宣言行、見出し不足 |
  | 段の不足 | 見出しが1件で2段の分類を使う | 2段目を最初に使うイベント宣言行、見出し不足 |
  | 見出しが0件 | `EventCategoryHeaders` | 見出し宣言行、見出しが必要 |
  | 上限超過 | 見出し名を4件並べる | 見出し宣言行、上限3段の超過 |
  | 空の名前 | `""`、`"   "` | 見出し宣言行、非空の見出し名が必要 |
  | 不正な構文 | 閉じる引用符なし、途中の引用符、引用符内の改行、区切りの省略、末尾の`>` | 見出し宣言行、構文が不正 |
  | 宣言の重複 | 有効な見出し宣言を2回記述する | 後の見出し宣言行、宣言の重複 |

- **WHEN** 内容を解析する。
- **THEN** 表の宣言行を指す理由付きの診断が返り、正常な文書全体の結果はなく、固定名の補完、切り捨てや後の宣言による上書きで受理されない。

### Requirement: REQ-022 - 分類経路と独立した列見出し名の指定

WHEN `.gls`を解析するとき、DSL解析機能は、行頭の`EventCategoryHeaders "<見出し名>"`と` > "<見出し名>"`で続けた文書単位の宣言を読み取り、分類の祖先から子の順に使う列見出し名を返さなければならない(SHALL)。\
宣言は文書内で最大1回、見出しは1件から3件とし、名前と空白と区切りの制約はREQ-018の分類名と同じとする。\
宣言位置はイベントより前でも後でもよく、分類付きイベントを使う最大深さ以上の件数を必要とする。\
未使用の段の名前を先に指定でき、名前は分類値やイベント名に補完しない。\
分類なしだけの文書では宣言を省略でき、既存のDSLを引き続き受け付ける。

#### Scenario: REQ-022-S01 - 各段の見出しを分類値と独立して読み取る

- **GIVEN** 次のいずれかの分類付きイベントと、その後に置いた列見出し宣言がある。

  | 分類経路 | 列見出し宣言 | 期待する列見出しの順 |
  | --- | --- | --- |
  | 操作 | `EventCategoryHeaders "系統"` | 系統 |
  | 操作 / 運転 | `EventCategoryHeaders "系統" > "区分"` | 系統、区分 |
  | 操作 / 運転 / 開始系 | `EventCategoryHeaders "領域" > "用途" > "種別"` | 領域、用途、種別 |

- **WHEN** 内容を解析する。
- **THEN** 列見出しは表の順で返り、イベントIDと名前と分類経路は元のままで、見出しを分類値から作ったり`系統`や`区分`に固定したりせず、診断はない。

#### Scenario: REQ-022-S02 - 未使用の段の見出しを指定しても既存イベントを保つ

- **GIVEN** 列見出しを`系統`、`区分`、`種別`の3件で宣言し、イベントは分類なしだけ、または1段の分類だけを使っている。
- **WHEN** 内容を解析する。
- **THEN** 列見出しは3件をそのまま保持し、イベントには省略した分類値を補わず、分類なしは分類なし、1段は元の1段だけとなり、診断はない。

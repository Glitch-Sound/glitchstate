# 提案

## 目的

状態遷移を設計する開発者は、現在のプレビューで状態の一覧を確認できるが、イベントと状態の組み合わせごとの処理や遷移先、定義漏れを確認できない。\
基本的なイベントと遷移を同じ`.gls`に記述し、既存の状態定義表と並べて状態遷移表を確認できるようにする。

## 変更内容

- DSLに平坦なイベントと、イベントと遷移元状態の組み合わせに対応する処理、遷移先の定義を追加する。
- 状態とイベントをIDで参照し、不正な参照や重複した組み合わせを診断する。
- イベントも定義順に並べ、定義済みセルでは処理なしと遷移なしをそれぞれ明示できるようにする。
- 既存の単一プレビューに状態遷移表を追加し、イベントを行、状態を定義順の列として表示する。
- 定義済みセルではラベルを付けずに処理を上段、遷移先を下段に表示し、定義のないセルは赤文字の`未定義`にする。
- 状態ヘッダには状態名を表示し、その文字色にDSLの状態カラーを使う。
- 未保存の変更、対象文書の切り替え、エラー時の正常表示の保持、再オープン後の更新を両方の表に適用する。
- 状態だけの既存DSLは引き続き有効とし、状態定義表の色、状態、意味の列順と、色見本だけの色列を保つ。

## 対象外

- イベント階層とカテゴリは、基本の行とセルの振る舞いを先に成立させるため含めない。
- 条件分岐、複数の遷移先、状態のグループ化は、単一の組み合わせに対する基本定義を超えるため含めない。
- 状態遷移図、選択の連動、拡大縮小、画像出力は、今回の表表示に必要ないため含めない。
- 処理の実行、イベントの発火、コード生成は含めない。

## 対象の仕様

### 新規

- `state-transitions`: 平坦なイベントと状態間の遷移を記述するDSL、参照、入力の検証を扱う。
- `state-transition-table`: 既存プレビュー内の状態遷移表と、その更新、エラー時の表示を扱う。

### 変更

- `state-definitions`: REQ-002の未対応記述の範囲を拡張後のDSLと整合させ、有効なイベントと遷移を誤って拒否しないようにする。

## 影響

- Coreの解析、検証、共通モデルと、ExtensionとWebview間で渡すモデルが拡張される。
- Webviewに表が増えるため、既存の状態定義表のテストは対象の表を明示する必要がある。
- README、DSLサンプル、仕様書の一覧、必要な実機確認項目を更新する。
- 新しいコマンドや外部依存は追加しない。

## 未決事項

- 状態またはイベントが0件の場合は、状態遷移表のセルを表示せず、不足する軸を案内する案とする。\
  両方が0件なら状態の不足を優先し、表の配置は状態定義表の下とする。\
  空の軸と未定義の組み合わせを区別するための暫定案であり、確認先は利用者とする。

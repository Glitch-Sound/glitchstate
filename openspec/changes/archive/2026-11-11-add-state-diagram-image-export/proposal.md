# 提案

## 目的

状態遷移をレビューする開発者は、既存プレビューの図を資料へ添付したり、拡大して参照したりするための画像を保存できない。\
画面の倍率と表示位置、操作中の選択に依存せず、現在表示できる図全体をPNGとSVGで共有できるようにする。

## 変更内容

- 図の操作部をGlitchFlowと同じ`-`、`Reset`、`+`、`⇩`、倍率表示の順にし、`⇩`の名前を`図をエクスポート`とする。
- 保存操作はPNGとSVGの形式選択、保存先の選択へ進み、対象の`.gls`と同じ基底名を初期ファイル名にする。
- 保存範囲は画面外を含む図全体とし、状態ノード、グループ枠と名前、全分岐先の個別矢印と集約矢印、自己ループと矢尻を含める。
- 選択強調を含めず、通常のノード背景、指定した状態カラー、現在のテーマの不透明背景と配色で保存する。
- 両表、見出し、図の操作部、倍率表示、案内と不可視の操作用要素は保存画像に含めない。
- 未保存の編集を反映した表示可能な図を保存し、解析エラーで保持した正常な図も対象とする。
- GlitchFlowの保存フローに合わせ、キャンセルで書き込まず、保存中の文書と図の更新では古い内容を取り違えて保存しない。
- PNG生成中に同じURI、version、sequenceと表示内容の通知が再送されても保存を継続し、実際の内容更新と文書切替による保存中止は維持する。
- 保存操作によって表示範囲、3表示の内容、状態選択、DSLと診断を変えない。

## 対象外

- 現在の表示範囲だけの保存、選択強調の保存、透明背景と白背景への切替。\
  利用者が選んだ1つの保存方針に絞る。
- 両表の画像保存、PDF保存、クリップボードへの画像コピー、連続出力。\
  今回の目的は図1件のPNGとSVG保存である。
- 図のレイアウト変更、図からの状態選択、DSLとCoreモデルの変更。\
  現在表示している図の意味と既存操作を維持する。
- エクスポートのための外部サービスと外部資源の取得。\
  ローカルで完結する既存方針に従う。

## 対象の仕様

### 新規

なし。

### 変更

- `state-transition-diagram`: PNGとSVGの保存操作、画像の内容、対象と結果の整合をREQ-041〜REQ-043として追加する。
- `state-transition-diagram`: 保存ボタンを許可するようREQ-030とREQ-038を変更し、既存IDと全シナリオ名を維持する。

既存の12要件に3要件を加え、変更後は15要件となる。

## 影響

- Webviewの図と操作部、画像生成、Extensionとの通信、Extensionの保存処理が対象となる。
- PNGとSVGの実画像、保存先のバイト列、キャンセルと更新競合を確認する自動テストを追加する。
- 同一通知の再送中のPNG保存を回帰テストに加え、既存のREQ-042-S05のPNGテストで通常遷移と自己ループの経路、矢尻の描画領域を個別に検査する。
- 既存の操作部の順序と件数の期待を4ボタンへ更新し、倍率、中心、矢印と選択の既存検査を保つ。
- READMEと正式仕様一覧の図の説明を更新する。
- 既存の`.gls`と状態遷移の意味、Coreの解析結果は変えない。

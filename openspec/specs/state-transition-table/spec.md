# state-transition-table Specification

## Purpose

開発者が既存のVS Codeプレビューでイベントと状態の組み合わせを一覧し、処理、遷移先、定義漏れを確認できるように、基本状態遷移表の軸、セル、状態カラー、編集中の更新を定める。

## Requirements

### Requirement: REQ-010 - イベントと状態を軸とする表

WHEN 有効な状態とイベントをプレビューするとき、プレビューは、既存の状態定義表と同じ画面内に、イベントを縦軸、状態を横軸とする状態遷移表を表示しなければならない(SHALL)。\
行と列はそれぞれの定義順とし、ヘッダにはIDではなくイベント名と状態名を表示する。\
状態ヘッダの文字色には、その状態のカラーを使う。\
同じ表示名でも異なるIDの行や列を統合せず、セルはイベントIDと遷移元状態IDの組み合わせで対応付ける。\
状態定義表の色、状態、意味の列順と色見本のみの色列を保つ。

#### Scenario: REQ-010-S01 - 定義順で軸とセルを対応付ける

- **GIVEN** 状態を`Z_IDLE`(待機、`#4F46E5`)、`A_RUN`(実行中、`#22C55E`)の順に、イベントを`Z_START`(開始)、`A_STOP`(停止)の順に定義し、各組み合わせに異なる処理と遷移先を定義している。
- **WHEN** 既存のコマンドでプレビューを表示する。
- **THEN** 同じ画面に状態定義表と状態遷移表があり、状態遷移表の列は`待機`、`実行中`、行は`開始`、`停止`の順である。
- **AND** 各処理と遷移先は指定したイベントと遷移元状態の交点にだけ表示される。
- **AND** 状態定義表の列は`色`、`状態`、`意味`の順であり、色セルには指定色の色見本だけがある。

#### Scenario: REQ-010-S02 - 同じ表示名の状態とイベントを区別する

- **GIVEN** 異なるIDの状態2件の表示名がともに`待機`で、異なるIDのイベント2件の表示名がともに`要求`であり、各組み合わせに異なる処理を定義している。
- **WHEN** 状態遷移表を表示する。
- **THEN** 状態の列は2列、イベントの行は2行のままで、各セルにはそのIDの組み合わせに対応する処理だけが表示される。

#### Scenario: REQ-010-S03 - 状態カラーをヘッダの文字色に使う

- **GIVEN** 待機のカラーが`#4F46E5`、実行中のカラーが`#22C55E`である。
- **WHEN** 状態遷移表を表示する。
- **THEN** `待機`のヘッダ文字は`#4F46E5`、`実行中`のヘッダ文字は`#22C55E`であり、色見本や背景色だけの指定にはならない。

### Requirement: REQ-011 - 処理と遷移先のセル表示

WHEN イベントと状態の組み合わせを表示するとき、状態遷移表は、分岐なしの定義済みセルの上段に処理、下段に遷移先の状態名を、項目ラベルを付けずに表示しなければならない(SHALL)。\
定義のないセルには、赤文字の`未定義`だけを表示する。\
処理の改行を保ち、処理、状態名、イベント名の文字列を表示用テキストとして扱う。\
処理なしの上段と遷移なしの下段にはそれぞれ`-`を表示し、両方がなしでも`未定義`にはしない。\
分岐付きの定義済みセルはREQ-025に従い、分岐なしセルを分岐の列へ変換しない。

#### Scenario: REQ-011-S01 - ラベルなしで処理を上段、遷移先を下段に表示する

- **GIVEN** `開始`と`待機`の組み合わせに、処理`開始を記録する`と遷移先ID`RUNNING`を定義し、その状態名が`実行中`である。
- **WHEN** 状態遷移表を表示する。
- **THEN** 対象セルの上段には`開始を記録する`だけ、下段には`実行中`だけがある。
- **AND** `処理`、`遷移先`のラベルや、遷移先ID`RUNNING`は表示されない。

#### Scenario: REQ-011-S02 - 定義のない組み合わせを赤文字で示す

- **GIVEN** 状態2件とイベント2件があり、4つの組み合わせのうち1つだけに処理と遷移先を定義している。
- **WHEN** 状態遷移表を表示する。
- **THEN** 定義済みセルにはその処理と遷移先があり、残りの3セルは赤文字の`未定義`だけである。

#### Scenario: REQ-011-S03 - 文字列を実行せず改行を保つ

- **GIVEN** 処理が`<script>window.glsExecuted = true</script>`と`確認する`の2行であり、イベント名と状態名に`<b>確認</b>`という文字列を含めている。
- **WHEN** 状態遷移表を表示する。
- **THEN** 処理の2行と各名前の文字列がそのまま表示され、`script`要素も`b`要素も生成されず、`window.glsExecuted`は設定されない。

#### Scenario: REQ-011-S04 - 明示的ななしと未定義を区別する

- **GIVEN** 次のいずれかの定義済みセルがある。

  | 処理 | 遷移先 | 上段 | 下段 |
  | --- | --- | --- | --- |
  | なし | RUNNING(実行中) | `-` | `実行中` |
  | 記録する | なし | `記録する` | `-` |
  | なし | なし | `-` | `-` |
  | 記録する | 遷移元IDLE(待機) | `記録する` | `待機` |

- **WHEN** 状態遷移表を表示する。
- **THEN** 上段と下段は表のとおりで、定義済みセルに`未定義`は表示されない。

### Requirement: REQ-012 - 軸の定義がない場合の表示

WHEN 状態またはイベントが0件の有効な文書をプレビューするとき、プレビューは、状態遷移表のデータ行やセルを表示せず、不足する軸を案内しなければならない(SHALL)。\
状態が0件なら状態がないことを優先して案内し、状態がありイベントが0件ならイベントがないことを案内する。\
以前の状態遷移表の行やセルは残さず、状態だけの既存文書の状態定義表は引き続き表示する。

#### Scenario: REQ-012-S01 - 状態だけの既存文書を表示する

- **GIVEN** 状態2件だけを定義した有効な既存の`.gls`文書がある。
- **WHEN** プレビューを表示する。
- **THEN** 状態定義表には2件が表示され、状態遷移表のデータ行とセルはなく、イベントがないことが案内される。

#### Scenario: REQ-012-S02 - 状態がなくなったら古いセルを消す

- **GIVEN** 状態遷移表を表示した後、文書を空にする、またはイベントだけの有効な文書へ変更している。
- **WHEN** プレビューが更新される。
- **THEN** 状態遷移表のデータ行とセルはなく、状態がないことが案内され、以前の処理や遷移先は表示されない。

### Requirement: REQ-013 - 両方の表を現在の文書に追従させる

WHEN プレビュー対象の内容が変わるとき、プレビューは、REQ-003、REQ-005、REQ-006の対象文書、保存前の更新、古い結果の拒否、診断と正常表示の保持を状態定義表と状態遷移表の両方に適用しなければならない(SHALL)。\
同じ正常な内容の両方の表を表示し、一方だけを新しい内容に置き換えない。\
同じURIを小さい版番号で開き直しても、自動更新とコマンド再実行を受け付ける。

#### Scenario: REQ-013-S01 - 未保存の編集を両方の表に反映する

- **GIVEN** 同じ文書の状態定義表と状態遷移表を表示し、保存は行わない。
- **WHEN** 次のいずれかの編集を行う。

  | 編集 | 期待する結果 |
  | --- | --- |
  | イベント名を変更する | 対象の行ヘッダが変わる |
  | 処理を変更する | 対象セルの上段だけが変わる |
  | 遷移先を別の有効な状態IDにする | 対象セルの下段が参照先の状態名になる |
  | 状態名とカラーを変更する | 状態定義表と状態ヘッダ、該当する遷移先表示が同じ変更を反映する |
  | 状態の宣言を入れ替える | 状態定義表の行と状態遷移表の状態列が同じ定義順になる |
  | イベントの宣言を入れ替える | 状態遷移表のイベント行だけが逆になる |
  | 参照されていないイベントまたは状態を追加、削除する | 対応する軸とセルが増減する |
  | 遷移定義を追加、削除する | 対象セルだけが定義済みと`未定義`の間で変わる |

- **THEN** 手動更新なしで表が期待する結果になり、文書は未保存のままである。

#### Scenario: REQ-013-S02 - 参照エラーで両方の正常な表を保つ

- **GIVEN** 正常な両方の表を表示している。
- **WHEN** 遷移先を未宣言IDへ変更する。
- **THEN** Problemsにはその遷移宣言行の参照エラーがあり、両方の表は最後の正常な内容を保つ。

#### Scenario: REQ-013-S03 - 別の文書へ切り替えたときに表を混在させない

- **GIVEN** 正常なA.glsの両方の表を表示し、B.glsには一度も正常に表示していない不正な参照がある。
- **WHEN** B.glsからプレビューコマンドを実行する。
- **THEN** B.glsの参照エラーが表示され、A.glsの両方の表はなく、解析エラーで表示できないことが案内される。

#### Scenario: REQ-013-S04 - 遅れた古い結果を両方の表に使わない

- **GIVEN** 状態名と処理を編集した最新の両方の表と診断が反映されている。
- **WHEN** 古い内容の解析結果または通知が遅れて届く。
- **THEN** 両方の表と診断は最新のままで、古い状態名、処理、遷移先、エラーには戻らない。

#### Scenario: REQ-013-S05 - 再オープン後も両方の表を更新する

- **GIVEN** プレビューを残して対象文書を閉じ、同じURIを閉じる前より小さい版番号で開き直している。
- **WHEN** 次のいずれかの操作を行う。

  | 操作 | 期待する結果 |
  | --- | --- |
  | コマンドを再実行せず状態名と処理を未保存のまま編集する | 同じプレビューの両方の表が編集後の内容になる |
  | 再オープンした文書からプレビューコマンドを再実行する | 既存の単一プレビューの両方の表が現在の内容になる |

- **THEN** 閉じる前より小さい版番号のままでも期待する結果になり、閉じる前の表は残らない。

#### Scenario: REQ-013-S06 - 修正後に両方の表と診断を回復する

- **GIVEN** 遷移先の未宣言IDに対する診断があり、両方の表は最後の正常な内容を表示している。
- **WHEN** 保存せずに遷移先を有効な別の状態IDへ修正する。
- **THEN** 両方の表は現在の内容になり、対象セルの下段は修正した遷移先の状態名になり、診断とエラー案内は消える。

### Requirement: REQ-020 - 状態遷移表のイベント側への分類表示

WHEN 分類付きイベントを状態遷移表へ表示するとき、プレビューは、イベント名の左側に祖先から子の順の分類名を表示し、宣言順の各イベント行と状態の列の交点を保たなければならない(SHALL)。\
分類領域の段数は文書の最大分類深さに合わせ、不足する段は空欄とし、固定の分類名や未分類の補完名を作らない。\
分類列にはREQ-022で指定した対応する見出し名を個別に表示し、その右のイベント名の列だけの見出しを`イベント`とする。\
分類列とイベント名を`イベント`の見出しで一括にまとめず、指定済みでも未使用の段の列と見出しは表示しない。\
同じ祖先を含む分類経路の共通部分だけを連続する行の範囲でまとめ、分類のために行を並べ替えず、イベント行自体は統合しない。\
分類なしだけの文書は、見出し宣言の有無にかかわらず既存のイベント列を維持する。\
分類名と列見出し名は文字列として表示し、状態定義表、図、セルの内容と指定カラーの意味を変えない。

#### Scenario: REQ-020-S01 - 指定した3段の分類名とイベント名を表示する

- **GIVEN** 状態`IDLE`(待機)と`RUNNING`(実行中)、イベント`START`(開始、分類`操作 / 運転 / 開始系`)があり、`IDLE`と`START`には処理`記録する`、遷移先`RUNNING`を定義している。
- **AND** 列見出しを`系統`、`区分`、`種別`の順に宣言している。
- **WHEN** 状態遷移表を表示する。
- **THEN** イベント側は左から`操作`、`運転`、`開始系`、`開始`の順で、状態列は定義順を保ち、対象の交点に上段`記録する`、下段`実行中`がある。
- **AND** 列見出しは左から`系統`、`区分`、`種別`、`イベント`、`待機`、`実行中`で、各分類列とイベント名の列が個別の見出しを持つ。
- **AND** 見出しを含め`分類1`、`分類2`、`分類3`の固定名や分類の代わりのIDは表示されない。

#### Scenario: REQ-020-S02 - 連続する共通の祖先分類だけをまとめる

- **GIVEN** イベントを`開始`(操作 / 運転)、`停止`(操作 / 運転)、`初期化`(操作 / 保守)の順に定義し、各行に異なる処理を持つセルがある。
- **AND** 列見出しを`系統`、`区分`の順に宣言している。
- **WHEN** 状態遷移表を表示する。
- **THEN** `操作`は3行をまとめた1つの分類セル、`運転`は最初の2行をまとめた1つの分類セル、`保守`は最後の行だけの分類セルとなる。
- **AND** イベント行は`開始`、`停止`、`初期化`の3行で、それぞれの処理が自分の行にある。

#### Scenario: REQ-020-S03 - 分類なしと浅い分類を混在させても交点をずらさない

- **GIVEN** イベントを`単独`(分類なし)、`操作`(分類は業務の1段)、`復旧`(分類は通信 / 監視 / 障害の3段)の順に定義し、各イベントと各状態の交点に異なる処理を定義している。
- **AND** 列見出しを`系統`、`区分`、`種別`の順に宣言している。
- **WHEN** 状態遷移表を表示する。
- **THEN** 分類領域は3段分あり、最初の行の分類はすべて空欄、2行目の分類は`業務`と残り2段分の空欄、最後の行の分類は`通信`、`監視`、`障害`となる。
- **AND** イベント名の列と状態列は各行でそろい、処理は元のIDの交点だけに表示され、空欄に`未分類`などの名前はない。
- **AND** 全イベントから分類を省略した文書では、見出し宣言が残っていても分類領域とその見出しはなく、見出し宣言のない既存文書と同じイベント列と状態列だけになる。

#### Scenario: REQ-020-S04 - 同名の子分類と離れた分類を統合しない

- **GIVEN** イベントを`甲`(業務 / 復旧)、`乙`(通信 / 復旧)、`丙`(業務 / 復旧)の順に定義している。
- **AND** 列見出しを`系統`、`区分`の順に宣言している。
- **WHEN** 状態遷移表を表示する。
- **THEN** 行順は`甲`、`乙`、`丙`のままで、各行は自分の祖先と子の分類を持ち、3行をまたいだ`復旧`の結合や、離れた`業務`をまとめるための並べ替えはない。

#### Scenario: REQ-020-S05 - 分類名を表示用テキストとして扱う

- **GIVEN** 分類名が`<script>window.glsCategoryExecuted = true</script>`、`<b>監視</b>`、`A > B`の3段である。
- **AND** 列見出し名を`<b>系統</b>`、`区分`、`種別`の順に宣言している。
- **WHEN** 状態遷移表を表示する。
- **THEN** 3つの分類名と`<b>系統</b>`を含む列見出し名の文字列がそのまま表示され、`A > B`は1つの分類セルであり、表内に`script`要素や`b`要素は作られず、`window.glsCategoryExecuted`は設定されない。

#### Scenario: REQ-020-S06 - 使用する段だけに指定した見出しを表示する

- **GIVEN** 状態が`待機`、`実行中`の順で、イベント`開始`が`操作 / 運転`へ分類され、見出しを`系統`、`区分`、`種別`の3件で宣言している。
- **WHEN** 状態遷移表を表示する。
- **THEN** 列見出しは左から`系統`、`区分`、`イベント`、`待機`、`実行中`の5件で、それぞれ対応する1列だけの見出しである。
- **AND** `種別`の列と見出し、分類列とイベント名を一括にまとめる見出しはなく、分類値`操作`と`運転`、イベント名`開始`はそれぞれ自分の列にある。

### Requirement: REQ-021 - 編集中のイベント分類と3表示の整合

WHEN プレビュー対象の分類または列見出しを編集するとき、プレビューは、REQ-013とREQ-017の更新と診断の規則を分類と列見出しにも適用し、保存前の現在の内容を状態遷移表へ反映しなければならない(SHALL)。\
分類名や所属だけの変更ではイベントIDに対応する処理、遷移先と図の関係を変えず、正常表示のない別文書や対象外の編集、古い通知を混入させない。\
分類や列見出しの誤りでは同じ文書の最後の正常な3表示を保持し、修正後は現在の分類と列見出し、図と両方の表へ回復して診断とエラー案内を消す。\
閉じる前より小さい版番号での再オープン後も、自動更新とプレビューコマンド再実行を受け付ける。

#### Scenario: REQ-021-S01 - 分類を未保存で編集しIDの対応を維持する

- **GIVEN** 分類付きイベントと階層なしイベントがあり、各IDに異なる処理と遷移先を定義し、3表示を開いている。
- **AND** 列見出しを3段分宣言している。
- **WHEN** 次のいずれかの編集を保存せずに行う。

  | 編集 | 期待する分類表示 |
  | --- | --- |
  | 分類名を変更する | 現在の名前へ変わる |
  | イベントを別の祖先の分類へ移す | 移動先の経路へ変わる |
  | 分類なしへ3段の分類を追加する | 3段とイベント名が現れる |
  | 全イベントの分類を省略する | 分類領域がなくなり既存のイベント列となる |
  | 分類付きイベントの宣言順を入れ替える | 宣言順で行と分類の連続範囲が変わる |

- **THEN** 手動更新なしで表の結果となり、各イベントIDの処理と遷移先、状態定義表、図のノードと矢印の関係は保たれ、文書は未保存のままである。

#### Scenario: REQ-021-S02 - 分類エラーで正常表示を保持し異なる現在の内容へ回復する

- **GIVEN** 分類`操作 / 運転 / 開始系`、状態名`待機`、処理`記録する`、遷移先`RUNNING`の正常な3表示を表示している。
- **AND** 列見出しは`系統`、`区分`、`種別`である。
- **AND** 分類を4段へ変更しており、イベント宣言行に深さの診断とプレビューにエラー案内があり、3表示は直前の正常な内容を保っている。
- **WHEN** 保存せず、分類を`業務 / 復旧`、列見出しを`領域`、`用途`、状態名を`再開待ち`、処理を`再開を記録する`、遷移先を以前と異なる有効な状態`RECOVERED`へ修正する。
- **THEN** 表の分類は`業務 / 復旧`、列見出しは`領域`、`用途`、図と両方の表の状態名は`再開待ち`、処理と矢印の終点と遷移先表示は修正後の内容となり、診断とエラー案内は消え、文書は未保存のままである。

#### Scenario: REQ-021-S03 - 古い通知と不正な分類通知を表示に使わない

- **GIVEN** 最新の分類`業務 / 復旧`と列見出し`領域`、`用途`の状態遷移表と、同じ内容の図と状態定義表を表示している。
- **WHEN** 次のいずれかの通知が届く。

  | 通知 | 内容 |
  | --- | --- |
  | 古い通知順の有効なモデル | 分類は以前の操作 / 運転、列見出しは系統、区分 |
  | 最新より後の通知順の不正なモデル | 分類が4段、空経路、空または空白だけの分類名、改行または二重引用符を含む分類名、文字列でない分類名、経路が配列でないまたはnull、のいずれか |
  | 最新より後の通知順の不正な列見出し | 宣言なしで分類あり、使用する段に不足、空配列、4件、空または空白だけの名前、改行または二重引用符を含む名前、文字列でない要素、配列でないまたはnull、のいずれか |

- **THEN** 現在の分類`業務 / 復旧`と列見出し`領域`、`用途`と3表示を保ち、古い分類や見出し、不正な内容へ変わらない。

#### Scenario: REQ-021-S04 - 小さい版番号で再オープンした分類を更新する

- **GIVEN** プレビューを残して対象文書を閉じ、同じURIを閉じる前より小さい版番号で開き直している。
- **WHEN** コマンドを再実行せず分類と列見出しを未保存で変更する、または再オープンした文書からプレビューコマンドを再実行する。
- **THEN** 同じ単一プレビューに現在の分類と列見出し、同じ内容の3表示が反映され、以前の分類や見出しは残らない。

#### Scenario: REQ-021-S05 - 別文書の分類を混在させない

- **GIVEN** A.glsの正常な分類付き3表示があり、B.glsには正常な表示履歴がなく分類の誤りがある。
- **WHEN** 次のいずれかを行う。

  | 操作 | 期待する結果 |
  | --- | --- |
  | B.glsを編集するだけ | 対象と3表示と診断はA.glsのまま |
  | B.glsからプレビューコマンドを実行する | B.glsの宣言行の診断と表示できない案内があり、A.glsの分類、図と両方の表のデータは残らない |

- **THEN** 操作に応じて表の結果となり、文書間の分類や正常表示が混在しない。

#### Scenario: REQ-021-S06 - 列見出しだけの編集と不足の修正を反映する

- **GIVEN** 2段の分類付きイベントと、列見出し`系統`、`区分`を持つ正常な3表示を開いている。
- **AND** 次の表の編集前の状態を用意し、不足診断のある状態では正常な3表示を保持している。
- **WHEN** 保存せずに表の編集を行う。

  | 編集前 | 編集 | 期待する結果 |
  | --- | --- | --- |
  | 正常 | 見出し名だけを領域、用途へ変更する | 見出しだけが変わり、分類値とイベントID、各セルの処理と遷移先、図は保たれる |
  | 正常 | 見出しを1件に減らす | 2段目を最初に使うイベント宣言行に不足診断とプレビューにエラー案内があり、以前の正常な見出しと3表示を保つ |
  | 見出しを1件にした不足診断あり | 領域、用途の2件へ修正する | 現在の見出しへ更新し、分類値とIDの対応を保ち、診断とエラー案内が消える |

- **THEN** 手動更新なしで表の結果となり、文書は未保存のままである。

### Requirement: REQ-025 - 共通処理の下だけを分割する分岐セル

WHEN 分岐付き遷移を状態遷移表へ表示するとき、表は、同じ状態とイベントの1つの交点の上部に共通処理を1回表示し、その下の分岐部分だけを定義順に左右へ並べ、隣接する分岐の境界を縦線で分けなければならない(SHALL)。\
各分岐は条件名、処理、遷移先の状態名を上から順に表示し、項目ラベルを付けない。\
縦線は共通処理の領域へ伸ばさず、共通処理を分岐ごとに繰り返さない。\
処理なしと遷移なしは各領域に`-`を表示し、分岐が1件でも定義済みとする。\
改行と文字列は表示用テキストとして保ち、長い内容を省略しない。\
分岐数で状態列やイベント行を増やさず、分岐なしのセル、赤文字の未定義、分類セルと指定した列見出し、状態の定義順とカラーを維持する。

#### Scenario: REQ-025-S01 - 共通処理の下の分岐だけを左右に分ける

- **GIVEN** `IDLE`と`START`の交点に、共通処理`要求を記録する`と、`準備完了`(開始する、RUNNING)と`それ以外`(拒否する、FAILED)の2分岐がある。
- **WHEN** 状態遷移表を表示する。
- **THEN** 共通処理は交点の上部に1回だけあり、その下の左側に`準備完了`、`開始する`、RUNNINGの状態名、右側に`それ以外`、`拒否する`、FAILEDの状態名がそれぞれ上から順にある。
- **AND** 左右の境界の縦線は分岐部分にだけあり、共通処理の領域に縦線はなく、`共通処理`、`条件`、`処理`、`遷移先`の項目ラベルはない。

#### Scenario: REQ-025-S02 - なしの各領域と1件の分岐を表示する

- **GIVEN** REQ-023-S02の各定義済み遷移があり、状態名はIDLEが`待機`、RUNNINGが`実行中`である。
- **WHEN** 状態遷移表を表示する。
- **THEN** 共通処理なしは上部の`-`、分岐の処理なしはその処理位置の`-`、遷移なしはその下段の`-`となり、自状態への明示的な遷移は`待機`となる。
- **AND** 条件名を持つ1分岐が表示され、空の2分岐目や内部の縦線、`未定義`はない。

#### Scenario: REQ-025-S03 - 異なる分岐数と分岐なしを交点の内側に保つ

- **GIVEN** 同じイベント行の状態ごとのセルに、1分岐、3分岐、分岐なし、未定義があり、それぞれの処理が異なる。
- **WHEN** 状態遷移表を表示する。
- **THEN** 状態列は定義した4列、イベントは元の1行のままで、各条件名と処理と遷移先は指定したIDの交点にだけある。
- **AND** 3分岐の下部は左から定義順の3領域となり、分岐なしは従来の上下2段、未定義は赤文字の`未定義`だけである。

#### Scenario: REQ-025-S04 - 分類付きイベントでも列と交点を維持する

- **GIVEN** 最大3段の分類、分類なしと浅い分類が混在し、連続する共通分類の結合と、`系統`、`区分`、`種別`の列見出しがある。
- **AND** 各イベントと状態の交点に、異なる共通処理と条件と処理を持つ分岐、または分岐なし遷移がある。
- **WHEN** 状態遷移表を表示する。
- **THEN** 分類の結合と不足段の空欄、各分類列とイベント列の個別の見出し、イベントの宣言順、状態列の横位置とカラーが保たれ、すべての共通処理と分岐は元の交点にある。
- **AND** 分岐部分の縦線は分類の領域へ伸びない。

#### Scenario: REQ-025-S05 - 条件と処理を文字列として表示し長い内容を欠落させない

- **GIVEN** 条件名が`<b>準備完了</b>`、共通処理と分岐の処理に`<script>window.glsBranchExecuted = true</script>`と続く行があり、別の分岐には折り返しを必要とする長い条件名と複数行の処理がある。
- **WHEN** 状態遷移表を表示する。
- **THEN** 各文字列と改行、末尾の内容まで表示され、表内に`b`や`script`要素は作られず、`window.glsBranchExecuted`は設定されない。
- **AND** 長い内容でも各分岐と隣の交点の内容が混ざらず、共通処理の下だけを分割した構造を保つ。

### Requirement: REQ-027 - 条件分岐の編集と3表示の整合

WHEN 対象文書の条件分岐を編集するとき、プレビューは、REQ-013、REQ-017、REQ-021の更新と診断の規則を分岐にも適用し、保存前の同じ内容を3表示へ反映しなければならない(SHALL)。\
条件や処理だけの変更で図の到達先を変えず、分岐の追加、除去、移動と分岐なしへの変更も現在の定義に追従する。\
分岐の誤りでは同じURIの最後の正常な3表示を保持し、修正後は現在の共通処理、条件、処理、遷移先、状態と分類へ回復して診断と案内を消す。\
対象外の編集、別文書の正常履歴、古い通知と不正な通知を混入させず、小さい版番号での再オープン、準備中の更新と図を含む描画完了の規則を維持する。

#### Scenario: REQ-027-S01 - 分岐と分類の未保存編集を反映する

- **GIVEN** 分類と列見出し、分岐付きセルと分岐なしセルを持つ正常な3表示を開いている。
- **WHEN** 保存せずに次のいずれかの編集を行う。

  | 編集 | 期待する結果 |
  | --- | --- |
  | 共通処理、条件名または分岐の処理だけを変更 | 表の該当部分が変わり、図の有向ペアは不変 |
  | 分岐の遷移先を別状態またはなしへ変更 | 表の下段と図の有向ペアが現在の定義と一致 |
  | 分岐の追加、除去または順序の入れ替え | 表の分岐数と左右の順が現在の定義となり、残る全分岐を図へ反映 |
  | 分岐なしと分岐付きを相互に置き換え | 同じ交点で従来の2段と分岐表示が切り替わり、古い内容は消える |
  | 分類の所属、列見出しまたはイベントの宣言順だけを変更 | 分類と行順だけが変わり、イベントIDに対応する共通処理と分岐を保持 |

- **THEN** 手動更新なしで表の結果となり、文書は未保存のままで、状態定義表と図と遷移表は同じ現在の内容を表す。

#### Scenario: REQ-027-S02 - 分岐エラーで保持して異なる内容へ回復する

- **GIVEN** 状態名`待機`、分類`操作 / 運転`、共通処理`要求を記録する`、条件`準備完了`、処理`開始する`、遷移先`RUNNING`の正常表示がある。
- **AND** 分岐の遷移先を未宣言の`MISSING`へ変更し、Branch行の診断とエラー案内があり、3表示は直前の正常な内容を保っている。
- **WHEN** 保存せず、状態名を`再開待ち`、分類を`業務 / 復旧`、共通処理を`再開要求を記録する`、条件を`復旧可能`、処理を`復旧する`、遷移先を別の有効な`RECOVERED`へ修正する。
- **THEN** 表の共通処理と条件と処理と遷移先、図の終点、両表と図の状態名、分類はすべて修正後の異なる内容であり、診断とエラー案内は消え、文書は未保存のままである。

#### Scenario: REQ-027-S03 - 古い通知と不正な分岐モデルを拒否する

- **GIVEN** 最新の共通処理と分岐を持つ正常な3表示がある。
- **WHEN** 古い通知順の有効なモデル、または新しい通知順の次の不正なモデルのいずれかが届く。

  | 不正な箇所 | 内容 |
  | --- | --- |
  | 共通処理と各分岐の処理 | 不足、空白だけ、文字列となし以外の値 |
  | 分岐の一覧 | 空配列、配列以外、なし、入れ子を含む要素 |
  | 条件名 | 不足、空または空白だけ、引用符または改行を含む、文字列以外、同じ遷移での重複 |
  | 分岐の遷移先 | 不足、不正な型やID形式、未宣言の状態ID |
  | 遷移の形式 | 分岐なしの項目と分岐付きの項目の混在、同じ交点の重複 |

- **THEN** 最新の3表示を保ち、古い共通処理や分岐へ戻らず、不正なモデルを補完して表示せず、その通知の描画完了を送らない。

#### Scenario: REQ-027-S04 - 小さい版番号で再オープンしても分岐を更新する

- **GIVEN** プレビューを残して文書を閉じ、同じURIを閉じる前より小さい版番号で開き直している。
- **WHEN** コマンドを再実行せず分岐を未保存で編集する、または再オープンした文書からプレビューコマンドを再実行する。
- **THEN** 既存の単一プレビューの3表示が現在の共通処理と分岐に変わり、古い条件や図の到達先は残らない。

#### Scenario: REQ-027-S05 - 別文書の分岐を混入させない

- **GIVEN** A.glsの正常な分岐付き3表示があり、B.glsには正常な履歴がなく分岐の誤りがある。
- **WHEN** B.glsを編集するだけ、またはB.glsからプレビューコマンドを実行する。
- **THEN** 編集だけなら対象と3表示と診断はA.glsのままであり、コマンド実行ならB.glsの宣言行の診断と表示できない案内になり、A.glsの共通処理、分岐、図と両表は残らない。

#### Scenario: REQ-027-S06 - 準備中と遅れた描画完了でも現在の分岐を保つ

- **GIVEN** 分岐付きの図の計測が完了する前に共通処理と条件と遷移先を変更している。
- **WHEN** 現在の図の準備が完了する、または以前の図の準備完了が遅れて届く。
- **THEN** 最初の3表示は現在の共通処理と条件と到達先に一致し、現在の図と両表の準備が完了してから現在のURIと版番号と通知順に対応する描画完了だけを送り、以前の図の完了で置き換えない。

# 提案

## 目的

状態遷移を設計する開発者は、イベントが増えると平坦な行から目的の処理を探しにくく、業務や操作の分類を表とDSLの両方で確認できない。\
既存のイベントと遷移を維持しながら、DSLで指定した最大3段の分類を状態遷移表へ表示できるようにする。

## 変更内容

- 分類を最大3段まで指定でき、その下にイベント名を表示する。\
  上限の3段にはイベント名を含めない。
- イベントごとに分類名の経路を任意で指定でき、階層なしイベントと混在できる。
- 分類経路とは別に、各段の列見出し名を文書単位でDSLへ指定する。\
  `系統`、`区分`のような指定した見出しを各列へ表示し、イベント名の列だけを`イベント`とする。\
  分類列とイベント名を1つの見出しにまとめない。
- 状態遷移表のイベント側に祖先から子の順で分類名を表示し、連続する共通の分類をまとめる。\
  イベントの行順は宣言順を保ち、分類のために並べ替えない。
- `分類1`、`分類2`などの固定の分類名や、階層のない箇所への補完名を表示しない。
- 分類を使う深さまでの列見出し名を必須とし、不足は診断する。\
  見出し名は最大3段まで先に指定でき、実際に使っていない段は表示しない。\
  分類なしだけの文書では、見出し宣言の有無にかかわらず従来のイベント列を保つ。
- イベントIDの文書内での一意性と遷移参照を維持し、分類名の変更や所属変更だけでは処理と遷移先を変えない。
- 保存前の分類と列見出しの編集、診断、正常表示の保持と修正後の回復を既存プレビューへ適用する。

## 対象外

- 条件分岐と状態グループは、イベントを分類する目的と独立しているため含めない。
- 分類の折り畳み、選択連動、図への分類表示は、表の分類表示に範囲を絞るため含めない。
- 分類値だけの独立した宣言、分類IDと分類を参照する遷移は設けない。\
  今回は文書単位の列見出しとイベントの分類経路を指定し、遷移は既存のイベントIDを使う。
- イベント宣言そのものの入れ子、分類によるイベントの自動整列は扱わない。

## 対象の仕様

### 新規

なし。

### 変更

- `state-transitions`: 平坦なイベントの既存記法を維持し、任意の分類経路、列見出しの宣言と最大深さ、入力検証を追加する。\
  REQ-007とREQ-009にある階層の禁止は、イベント宣言自体の入れ子の禁止として限定する。
- `state-transition-table`: イベント側の分類名と所属、個別の列見出し、混在する深さ、連続範囲の表示と編集中の更新を追加する。

## 影響

- Coreのイベント解析と共通モデル、ExtensionとWebviewの通知検証、状態遷移表のイベント側を拡張する。
- 分類を省略した既存DSLとモデルを維持し、状態定義表、状態遷移図、セルの処理と遷移先の意味を保つ。
- Coreの単体、通信境界、表のブラウザ、実VS Codeの統合テストを追加する。
- READMEと分類のサンプル、既存仕様の一覧の説明を更新する。\
  新しい依存は追加しない。

## 未決事項

- 分類セルの余白は既存の表の値を初期値とする。\
  分類の境界と長い名前の読みやすさを確認し、必要なら表示だけを調整する。

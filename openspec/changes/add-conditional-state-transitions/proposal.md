# 提案

## 目的

状態遷移を設計する開発者は、同じ状態とイベントでも条件によって処理と遷移先が異なる場合、現在の単一の処理と遷移先だけでは設計を表せない。\
共通処理と条件ごとの処理を分けて定義し、表で比較しながら図で到達先を確認できるようにする。

## 変更内容

- DSLで共通処理と、名前付きの条件ごとの処理と遷移先を定義できるようにする。\
  分岐は入れ子のない1段とし、条件名は評価しない表示用テキストとする。\
  `それ以外`も通常の条件名として扱い、特別な評価順や既定分岐を作らない。
- 共通処理と各分岐の処理なし、各分岐の遷移なしを独立して明示できるようにする。
- 状態遷移表では、対象の交点の上部へ共通処理を1回だけ表示する。\
  その下の分岐部分だけを条件の定義順で左右に並べ、隣の分岐との境界を縦線で区切る。\
  各分岐には条件名、処理、遷移先の状態名を上から順に表示する。
- 図では各分岐の遷移先を既存の状態間の矢印へ反映する。\
  同じ有向ペアの集約、遷移なしの省略、自己ループ、淡い配色とラベルなしの表示を維持する。
- 保存前の編集、宣言行の診断、正常な3表示の保持と修正後の回復を条件分岐にも適用する。
- 既存の分岐なし遷移の記法と表示、イベントIDの参照、最大3段のイベント分類と独立した列見出しを維持する。

## 対象外

- 状態グループは条件ごとの到達先を表す目的と独立しているため含めない。
- 分岐の入れ子、条件式の実行や真偽判定、排他性や網羅性の判定、専用のElse構文は含めない。\
  今回は設計情報として列挙した名前付き分岐を表示する。
- 条件名や処理の図上ラベル、条件を表す菱形ノード、イベント分類の図への表示、選択連動、操作ボタンと画像保存は含めない。

## 対象の仕様

### 新規

なし。

### 変更

- `state-transitions`: 共通処理と名前付き分岐の読み取りと診断を追加し、REQ-008とREQ-009の既存の分岐なし遷移の範囲と条件分岐の拒否を整合させる。\
  REQ-009-S01の未対応例は新しい有効記法と区別し、既存IDとシナリオ名を維持する。
- `state-transition-table`: 分岐セルの共通処理と下部だけの縦分割、編集中の3表示の整合を追加し、REQ-011の上下2段の表示を分岐なしの規則として明確にする。
- `state-transition-diagram`: 各分岐からの状態間の矢印を追加し、REQ-015の矢印の対象へ分岐の到達先を含める。

## 影響

- Coreの解析と検証、共通モデル、ExtensionとWebviewの通知検証、表のセルと図の遷移変換を拡張する。
- 既存の文書管理、正常モデルと通知順の管理を利用し、分類と条件分岐を別々に保持する表示専用の情報源は追加しない。
- Core、通知境界、セルと図のブラウザ、実VS Codeの統合テストを追加する。
- README、分岐と分類が共存するサンプル、仕様一覧の説明を更新する。\
  新しい依存は追加しない。

## 未決事項

- 分岐間の余白と縦線は既存の表の余白とテーマ色を初期値とする。\
  長い条件名や複数行の処理でも内容を欠落させず、必要な調整は表示だけに限定する。

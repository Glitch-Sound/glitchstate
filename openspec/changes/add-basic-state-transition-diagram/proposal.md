# 提案

## 目的

開発者は、既存の状態定義表と状態遷移表から各状態の内容とイベントごとの処理を確認できるが、状態間の到達関係や自己遷移を図として俯瞰できない。\
同じプレビュー内に基本状態遷移図を加え、DSLを変更すると3つの表示から同じ設計を確認できるようにする。

## 変更内容

- 状態定義表、状態遷移図、状態遷移表の順で表示する。
- 各状態のIDを識別に使い、状態名と指定カラーを持つノードを表示する。
- 遷移先を持つ遷移を方向付きの淡い矢印で示し、イベント名を図に表示しない。
- 同じ遷移元と遷移先の矢印を1本にまとめ、逆方向は別の矢印、自状態への遷移は自己ループで示す。
- 遷移なしと未定義の組み合わせには矢印を作らず、遷移のない状態もノードとして表示する。
- 保存前の変更、対象文書、古い結果の拒否、正常表示の保持と回復を、既存の2表と図に適用する。

## 対象外

- グループとイベント階層、条件分岐は、基本の状態間の関係に範囲を絞るため含めない。
- 状態選択に連動する強調は、表示領域間の操作設計を別の変更で扱うため含めない。
- 操作ボタン、画像保存、配置のDSL指定と保存は、図を表示する基本機能とは分けて扱う。
- DSLの記法、Coreの共通モデル、既存2表の列とセルの意味は変更しない。

## 対象の仕様

### 新規

- `state-transition-diagram`: 状態ノード、有向矢印、自己ループ、重複する状態間の関係、図の配色と3表示の整合を扱う。

### 変更

なし。\
既存の4仕様を確認し、図の描画に関する要件は表の仕様へ混在させず、独立したcapabilityへ追加する。

## 影響

- 既存の`.gls`と状態定義、イベント、遷移の共通モデルをそのまま利用する。
- Webviewのプレビュー構成と図の描画、Webviewビルドのスタイル、描画完了の扱いを変更する。
- 単体テスト、ブラウザテスト、VS Code統合テストへ図の検証を追加する。
- `README.md`と`openspec/specs/README.md`を更新し、図の関連ファイルの置き場所を`openspec/structure.md`へ反映する。
- 新しい依存は追加せず、既存のReact Flowを利用する。

## 未決事項

- ノードの指定カラーを使う箇所は、状態名の文字色と淡い背景を初期案とする。\
  読みやすさを保ち、不要な枠を増やさないためであり、具体的な濃さは設計値として調整する。
- 自動配置の列数、間隔、図領域の高さ、矢印の淡さと空状態の案内文は、設計の初期値を使う。\
  配置の保存や操作を伴わず変更できるため、実装を止める事項にはしない。
- 図内のパンとホイール拡大縮小は、操作ボタンを設けず標準操作を残す初期案とする。\
  ノードの移動、接続編集、選択は無効にし、操作の範囲は設計で明示する。

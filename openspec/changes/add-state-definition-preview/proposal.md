# 提案

## 目的

状態設計を行う開発者が、`.gls`ファイルに状態を定義しながら、その内容をVS Codeの状態定義表で確認できるようにする。\
現状は起動確認用のプレビューだけであり、状態定義を読み取る機能がないため、保存前の編集にも追従する最初の設計機能を提供する。

## 変更内容

- `.gls`ファイルで状態ID、状態名、意味、カラーを定義し、定義を並べた順に表示できるようにする。
- 利用者から記法と入力制約の設計を委ねられたため、GlitchFlowの宣言とインデント付き本文を参考に状態の記法を設計する。
- VS Codeのプレビューに状態定義表を表示する。
- 保存前のDSL変更を自動で表へ反映する。
- CoreでDSLを構文解析し、表示用の共通モデルを生成する。
- 解析エラーをVS Codeの診断で伝え、最後の正常な描画を保持する。

## 対象外

- イベント、遷移、条件分岐、グループの定義と表示は、状態定義から独立して追加できるため扱わない。
- 状態遷移図、状態遷移表、表示領域間の選択連携は、今回の状態定義表の確認に必要ないため扱わない。
- 構文ハイライト、入力補完、整形、画像エクスポートは、定義とプレビューの往復を成立させるために必須ではないため扱わない。

## 対象の仕様

### 新規

- `state-definitions`: DSLによる状態定義と表示順序を扱う。
- `state-definition-preview`: VS Codeでの状態定義表の表示、保存前の変更反映、解析エラー時の表示を扱う。

### 変更

なし。

## 影響

- `src/core/`に構文解析、定義検証、表示用共通モデルを追加する。
- `src/extension/`に`.gls`の言語登録、文書とプレビューの連携、変更監視、診断通知を追加する。
- `src/webview/`の起動確認画面を状態定義表に置き換える。
- `package.json`、既存のテスト設定、`tests/`を更新し、実際の文書変更とメッセージ通信を検証できるようにする。
- `README.md`と`examples/`に記法と使い方を追加し、`openspec/specs/README.md`に仕様の関係を記載する。

## 未決事項

- プレビューの開き方は、既存の`glitchstate.openPreview`コマンドを使い、対象の`.gls`文書を単一のプレビューへ結び付ける案を仮に採用する。\
  別の文書への切り替えも同じコマンドで行い、自動で開く機能は今回含めない。\
  既存の入口を使って状態定義の表示に範囲を絞れるためであり、利用者の希望があれば見直す。
- 表の列見出しは状態名、意味、カラーとし、カラーは色見本と値を表示する案を仮に採用する。\
  状態IDは共通モデルに保持し、表の追加列にはしない。\
  状態定義の確認に必要な情報を優先するためであり、表示文言と列構成は利用者の希望があれば見直す。

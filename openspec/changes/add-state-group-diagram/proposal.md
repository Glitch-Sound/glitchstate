# 提案

## 目的

状態遷移を設計する開発者は、関連する複数状態から同じ状態へ進む関係を確認するとき、個々の矢印が重なって共通の到達先を追いにくい。\
DSLで明示した状態群を図で囲み、複数メンバーから同じ外部状態への矢印を枠からの1本にまとめ、個別の処理と遷移を表で確認できるようにする。

## 変更内容

- DSLに名前付き状態グループを追加する。\
  記法と入力制約の設計は利用者から委ねられており、2状態以上の平坦なグループとし、入れ子と同じ状態の複数グループへの所属は認めない。
- 図ではグループ名と実線の枠を表示し、所属する状態ノードだけを囲む。\
  個々の状態名とカラー、グループ外の状態を保つ。
- 同じグループ内の異なる2状態以上から同じグループ外の状態へ向かう遷移を、枠から対象状態への1本に集約する。\
  全メンバーの一致は要求せず、イベントと条件分岐をまたいで判断し、集約対象の個別矢印を重ねない。
- 1状態だけからの遷移、グループ内への遷移、自己遷移は個々の状態の矢印を保つ。\
  到達先が別グループに所属していても終点はその状態とし、グループの枠を終点にしない。
- 状態とイベントの定義順、個々の分岐なし遷移と条件分岐、共通処理、分類と列見出しを保ち、状態定義表と状態遷移表をグループ単位へ統合しない。
- 保存前のグループ編集、診断、正常な3表示の保持と現在の内容への回復、再オープンと描画完了の規則を適用する。

## 対象外

- 1状態から複数状態への矢印の集約と、到達先グループの枠への集約は含めない。\
  今回の目的は複数の遷移元から同じ状態への関係の整理である。
- グループの入れ子と重複所属、グループを遷移の参照先にする記法、状態選択の連動、グループの折り畳みや編集操作は含めない。
- 条件の評価、遷移定義の継承や自動生成、図の操作ボタンと画像保存は含めない。\
  グループは図の表現であり、設計情報の実行意味は増やさない。

## 対象の仕様

### 新規

なし。

### 変更

- `state-definitions`: グループ宣言と所属状態の読み取り、構造と参照の診断を追加し、REQ-002の未対応記述の範囲へ有効なStateGroup宣言を含める。\
  既存の`Group STATES`の不正例と既存シナリオのIDと名前は維持する。
- `state-transition-diagram`: 実線のグループ枠、外部の同一状態への矢印集約、編集時の整合を追加し、REQ-014、REQ-015、REQ-026の状態ノードと矢印の規則へ明示した例外を整合させる。
- `state-transition-table`: グループの有無にかかわらず個々の状態と遷移、分類と条件分岐の意味と表示を維持することを追加する。

## 影響

- CoreのDSL解析と共通モデル、通知境界、図の配置と接続、描画完了を拡張する。\
  既存のURIごとの正常モデルと通知順の管理を利用する。
- Core、通知境界、図の単体とブラウザ、Extension単体と実VS Code統合のテストを追加する。
- README、分類と条件分岐を含むグループのサンプル、仕様一覧を更新する。\
  新しい依存は追加しない。

## 未決事項

- 枠と名前の余白と太さは既存の図の間隔とテーマ色を初期値とする。\
  長い名前と複数行の状態名が欠落せず、自己ループが枠外へ出ない範囲で表示だけを調整する。

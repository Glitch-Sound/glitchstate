# 差分仕様

## ADDED Requirements

### Requirement: REQ-023 - 共通処理と名前付き分岐の読み取り

WHEN `.gls`を解析するとき、DSL解析機能は、`Transition <状態ID> on <イベントID>:`の下に共通処理と1件以上の名前付き分岐を読み取り、1つの定義済み遷移として返さなければならない(SHALL)。\
半角空白4個で下げた`Common:`を最初に1回、その後に同じ深さの`Branch "<条件名>" -> <遷移先>:`を定義順に置き、各処理は半角空白8個で下げた1行以上とする。\
遷移先は状態IDまたは`-`とし、ID参照、改行と空白行はREQ-008に従う。\
共通処理と各分岐の処理は、単独の`-`でなしを明示できる。\
条件名は非空白の文字列で、引用符、改行とエスケープの制約はREQ-007の名前と同じとする。\
キーワード間は半角空白1個以上、行末の半角空白を許可し、引用符内の空白を保つ。\
条件名は評価せず、入れ子と専用のElse構文は設けない。

#### Scenario: REQ-023-S01 - 共通処理と各分岐を定義順に読み取る

- **GIVEN** 状態`IDLE`、`RUNNING`、`FAILED`とイベント`START`があり、次の遷移を定義している。

  ```gls
  Transition IDLE on START:
      Common:
          要求を記録する
      Branch "準備完了" -> RUNNING:
          開始する
      Branch "それ以外" -> FAILED:
          拒否を記録する
  ```

- **WHEN** 文書全体を解析する。
- **THEN** `IDLE`と`START`の定義は1件で、共通処理は`要求を記録する`、分岐は`準備完了`(開始する、RUNNING)、`それ以外`(拒否を記録する、FAILED)の順で返り、診断はない。
- **AND** 共通処理を各分岐へ複写せず、`それ以外`にも暗黙の条件判定や特別な順序を付けない。

#### Scenario: REQ-023-S02 - 1件の分岐と明示的ななしを保持する

- **GIVEN** 有効な参照を持つ遷移を1件の分岐だけで定義し、次のいずれかを指定している。

  | 共通処理 | 分岐の処理 | 分岐の遷移先 | 期待する結果 |
  | --- | --- | --- | --- |
  | `-` | 記録する | RUNNING | 共通処理なし、処理あり、RUNNINGへの分岐 |
  | 記録する | `-` | RUNNING | 共通処理あり、処理なし、RUNNINGへの分岐 |
  | 記録する | 処理する | `-` | 共通処理と処理あり、遷移なしの分岐 |
  | `-` | `-` | `-` | すべてなしの定義済みの1分岐 |
  | 記録する | 処理する | IDLE | 遷移元IDLEへの明示的な分岐 |

- **WHEN** 内容を解析する。
- **THEN** 表の結果の1分岐が返り、処理なしを欠落や空文字へ、遷移なしを自己遷移へ、定義済みセルを未定義へ置き換えず、診断はない。

#### Scenario: REQ-023-S03 - 複数行と分類付きイベントの後方参照を保持する

- **GIVEN** 分岐遷移より後に状態と、2段に分類したイベント`START`、必要な分類列見出しを宣言している。
- **AND** 共通処理は`要求を記録する`と`準備する`、分岐の処理は`開始する`と`通知する`の2行で、CRLFと空白行、複数のキーワード間空白、行末空白を含む。
- **AND** 条件名は` A > B `である。
- **WHEN** 内容を解析する。
- **THEN** 共通処理と分岐の処理はそれぞれの2行だけをLFで連結し、条件名は前後の空白と`>`を含むまま、イベントIDと分類、列見出し、状態への参照も保持され、診断はない。

#### Scenario: REQ-023-S04 - 分岐なし本文の文字列を分岐として解釈しない

- **GIVEN** 既存形式の`Transition IDLE on START -> RUNNING:`の本文を半角空白4個で下げ、`Common:`と`Branch "確認" -> IDLE:`という表示用テキストを記述している。
- **WHEN** 内容を解析する。
- **THEN** 分岐なし遷移が1件で、処理は2行の文字列、遷移先は`RUNNING`のままであり、共通処理や条件分岐への変換はなく、診断はない。

### Requirement: REQ-024 - 分岐遷移の誤りの報告

IF 分岐遷移の構文、名前、処理、参照、順序がREQ-023の制約を外れる、同じ遷移内で条件名が重複する、または分岐の有無によらず状態IDとイベントIDの組み合わせが重複する場合、THEN DSL解析機能は、その位置と理由を診断し、文書全体を正常な結果として返してはならない(SHALL)。\
条件名の重複は大小文字や引用符内の空白を変換せず完全一致で判定する。\
共通処理の不足はCommon行、分岐の処理不足と遷移先の誤りはBranch行、Commonまたは分岐の宣言自体がない場合はTransition行を指す。\
構文、インデントと順序の誤りはその行、条件名と組み合わせの重複は後の宣言行を指す。\
共通処理と各分岐で`-`と他の非空本文が混在したら、その処理の2つ目の非空行を指す。

#### Scenario: REQ-024-S01 - 構造と処理の誤りを該当行で診断する

- **GIVEN** 有効な分岐遷移の1か所だけを、次のいずれかに変えている。

  | 誤り | 診断対象と理由 |
  | --- | --- |
  | Common宣言がない | Transition行、共通処理宣言の不足 |
  | Common本文が空白だけまたはない | Common行、処理またはなしの指定の不足 |
  | Branch宣言が0件 | Transition行、分岐の不足 |
  | Branch本文が空白だけまたはない | Branch行、処理またはなしの指定の不足 |
  | 条件名が空または空白だけ | Branch行、非空の条件名が必要 |
  | 条件名に途中の引用符や改行、閉じ忘れがある | Branch行、条件名の構文 |
  | Branchの矢印、遷移先、末尾のコロンのいずれかがない | Branch行、分岐の構文 |
  | Commonを2回書く | 後のCommon行、共通処理宣言の重複 |
  | Branchの後に初めてCommonを書く | Common行、共通処理の順序 |
  | 宣言や本文を2個、6個の空白またはタブで下げる | その行、インデント |
  | Branchの中へさらにBranchと12個の空白の本文を入れる | 12個で下げた行、未対応の入れ子またはインデント |
  | 共通処理、または1つの分岐の処理で`-`と他の行を混在させる | 対象の2つ目の非空本文行、処理なしの混在 |
  | 分岐付き宣言の下に旧形式の4個の空白の処理を直書きする | その行、共通処理または分岐の宣言が必要 |

- **WHEN** 各内容を解析する。
- **THEN** 表の位置と理由の診断があり、正常なモデルはなく、不正な部分の破棄や分岐なしへの読み替えで受理しない。

#### Scenario: REQ-024-S02 - 条件名の重複を遷移単位で判定する

- **GIVEN** 次のいずれかの条件名を持つ、有効な本文と参照を定義している。

  | 定義 | 期待する結果 |
  | --- | --- |
  | 同じ遷移内で`準備完了`を2回 | 後のBranch行に条件名の重複診断、正常モデルなし |
  | 異なる遷移内でそれぞれ`準備完了` | それぞれの条件名を保持し、診断なし |
  | 同じ遷移内で`Ready`と`ready` | 大小文字を保つ2分岐で診断なし |

- **WHEN** 内容を解析する。
- **THEN** 表の結果となり、同じ遷移で重複した条件を上書きせず、他の遷移の同名条件を混同しない。

#### Scenario: REQ-024-S03 - 各参照の形式と宣言を検証する

- **GIVEN** 次の参照の1つだけを、形式が不正な`1BAD`、または未宣言の`MISSING`へ変えている。

  | 参照 | 診断の対象 |
  | --- | --- |
  | 遷移元状態 | Transition行 |
  | イベント | Transition行 |
  | 分岐の遷移先状態 | そのBranch行 |

- **WHEN** 各内容を解析する。
- **THEN** 表の行に、参照種別と形式の誤り、または参照種別と`MISSING`の未宣言を示す診断があり、正常な文書全体の結果は返らない。

#### Scenario: REQ-024-S04 - 分岐の有無をまたぐ交点の重複を拒否する

- **GIVEN** 同じ状態`IDLE`とイベント`START`に対して、分岐なしと分岐付き、分岐付きと分岐なし、または分岐付き2件の順で遷移を重複定義している。
- **WHEN** 各内容を解析する。
- **THEN** 後のTransition行に`IDLE`と`START`の組み合わせの重複診断があり、正常モデルは返らず、2つの定義の合成や後勝ちの上書きはない。

## MODIFIED Requirements

### Requirement: REQ-008 - 状態とイベントに対応する処理と遷移先の読み取り

WHEN `.gls`を解析するとき、DSL解析機能は、行頭の`Transition <遷移元状態ID> on <イベントID> -> <遷移先>:`と、直後の半角空白4個で始まる処理本文を分岐なしの遷移として読み取り、その組み合わせの処理と遷移先を返さなければならない(SHALL)。\
遷移先は状態IDまたは`-`とする。\
IDは宣言済みの状態またはイベントを参照し、宣言の前後関係を問わない。\
処理は1行以上の非空本文を必須とし、インデントと改行の扱いはREQ-001の意味と同じとする。\
本文の非空行が1行で`-`だけなら処理なし、遷移先の`-`は遷移なしを明示し、両方を独立して指定できる。\
処理なしと遷移なしを組み合わせても定義済みであり、遷移なしを遷移元への参照に置き換えない。\
遷移元と同じ状態IDを指定した場合は、その状態への明示的な遷移として保持する。\
共通処理と条件ごとの処理と遷移先を持つ分岐付き遷移はREQ-023に従い、同じ状態とイベントの組み合わせではどちらか一方だけを定義する。

#### Scenario: REQ-008-S01 - 各参照と処理を読み取る

- **GIVEN** 状態`IDLE`、`RUNNING`、イベント`START`と、次の定義がある。

  ```gls
  Transition IDLE on START -> RUNNING:
      開始を記録する
  ```

- **WHEN** 内容を解析する。
- **THEN** `IDLE`と`START`の組み合わせに処理`開始を記録する`、遷移先`RUNNING`が1件返り、エラーはない。

#### Scenario: REQ-008-S02 - 複数行、空白行と改行形式を扱う

- **GIVEN** 有効な参照を持つ遷移の処理を、半角空白4個で下げた`開始を記録する`と`実行を準備する`の2行で記述している。
- **AND** 次のいずれかの形式で記述している。

  | 改行形式 | 処理の行間の空白だけの行 |
  | --- | --- |
  | LF | あり |
  | CRLF | なし |

- **WHEN** 内容を解析する。
- **THEN** 処理は`開始を記録する`と`実行を準備する`をLFで連結した文字列であり、空白行と先頭のインデントは含まず、エラーはない。

#### Scenario: REQ-008-S03 - 処理なしと遷移なしを独立して保持する

- **GIVEN** 有効な遷移元`IDLE`とイベント`START`に対し、次のいずれかを定義している。

  | 処理本文 | 遷移先 | 期待する結果 |
  | --- | --- | --- |
  | `-` | `RUNNING` | 処理なし、遷移先RUNNINGの定義済み遷移 |
  | `記録する` | `-` | 処理は記録する、遷移なしの定義済み遷移 |
  | `-` | `-` | 処理なし、遷移なしの定義済み遷移 |

- **WHEN** 内容を解析する。
- **THEN** 表の結果どおりに1件が返り、組み合わせが未定義になったり、遷移先が`IDLE`に補われたりせず、エラーはない。

#### Scenario: REQ-008-S04 - 後方の宣言と自状態への参照を解決する

- **GIVEN** 文書の最初に`Transition IDLE on START -> IDLE:`と処理を記述し、その後に状態`IDLE`とイベント`START`を宣言している。
- **WHEN** 文書全体を解析する。
- **THEN** 遷移先は状態`IDLE`への明示的な参照となり、遷移なしには変換されず、エラーはない。

### Requirement: REQ-009 - 不正なイベントと遷移の報告

IF イベントまたは分岐なし遷移がREQ-007、REQ-008の構文と入力制約を外れる、イベントIDが重複する、状態やイベントの参照先が存在しない、または同じ遷移元状態IDとイベントIDの組み合わせを重複定義する場合、THEN DSL解析機能は、その位置と理由を診断し、文書全体を正常な結果として返してはならない(SHALL)。\
重複は後の宣言行、参照の誤りと必須本文の不足は遷移宣言行、不正な本文インデントは本文行を指す。\
本文に`-`だけの行がある場合は他の非空行を許可せず、2つ目の非空本文行を指す。\
イベント宣言自体の入れ子とREQ-023に合わない条件分岐の構文は受け付けず、平坦な処理本文は表示用テキストとして扱う。\
分岐付き遷移の誤りはREQ-024に従う。

#### Scenario: REQ-009-S01 - 構文と入力制約の誤りを診断する

- **GIVEN** 有効な文書の1か所だけを、次のいずれかに変更している。

  | 不正な箇所 | 入力例 | 診断の対象と理由 |
  | --- | --- | --- |
  | イベントの要素不足 | `Event START` | イベント宣言行、構文 |
  | イベントID | `Event 1START as "開始"` | イベント宣言行、ID |
  | イベント名 | `""`、`"   "` | イベント宣言行、名前 |
  | イベント名の引用符 | 閉じる引用符なし、途中の引用符、引用符内の改行 | イベント宣言行、構文 |
  | 分岐なし遷移の要素不足 | `on`、`->`、末尾の`:`、遷移先のいずれかを省略 | 遷移宣言行、構文 |
  | 参照IDの形式 | 遷移元、イベント、遷移先のいずれかが`1INVALID` | 遷移宣言行、ID |
  | 処理の不足 | 宣言直後が文書末尾、または空白行だけ | 遷移宣言行、処理 |
  | 処理のインデント | 半角空白2個、8個、タブ1個 | 処理の行、インデント |
  | 処理なしの混在 | 処理本文に`-`と`記録する`の2行 | 2つ目の非空本文行、処理なしの混在 |
  | イベント宣言の入れ子 | イベント宣言の下に半角空白4個で下げた別のイベント宣言 | 子の宣言行、未対応のイベント階層 |
  | 未対応形式の条件分岐 | 分岐なし遷移の本文内に半角空白4個で下げた`If READY:`と8個で下げた処理 | 8個で下げた行、未対応のインデント |

- **WHEN** 内容を解析する。
- **THEN** 表の対象行を指す診断と該当する理由が返り、正常な文書全体の結果は返らない。

#### Scenario: REQ-009-S02 - 参照先がないIDを診断する

- **GIVEN** 有効な遷移の遷移元状態ID、イベントID、遷移先状態IDのうち、1つだけを未宣言の`MISSING`にしている。
- **WHEN** 各内容を解析する。
- **THEN** 遷移宣言行に、未宣言の参照種別と`MISSING`を示す診断が返り、正常な結果は返らない。

#### Scenario: REQ-009-S03 - イベントと組み合わせの重複を診断する

- **GIVEN** 次のいずれかの重複がある。

  | 重複 | 期待する診断 |
  | --- | --- |
  | イベントID`START`を2回宣言する | 2つ目のイベント宣言行にイベントIDの重複 |
  | `IDLE`と`START`の組み合わせを2回定義する | 遷移先や処理が異なっていても、2つ目の遷移宣言行に組み合わせの重複 |

- **WHEN** 各内容を解析する。
- **THEN** 表の位置と理由の診断が返り、後の宣言で上書きした正常な結果は返らない。

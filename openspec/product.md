# プロダクト

プロダクトの目的と範囲を定め、変更の判断の基準にする。\
具体的な振る舞いと要件は specs に書き、ここには書かない。

## 目的

GlitchStateは、状態遷移を設計するソフトウェア開発者向けのVS Code拡張機能である。

状態定義・状態遷移図・状態遷移表が別々の資料で管理されることによる、情報の分散、整合性の欠如、設計漏れを解消する。\
独自DSLを単一の定義元とし、3つの表現を一体的に可視化することで、状態とイベントの関係、処理内容、遷移先、条件分岐を俯瞰できるようにする。

設計内容の理解とレビューを容易にし、状態遷移に起因する不具合の予防と、ソフトウェア品質の向上を目指す。\
GlitchBoard・GlitchFlowと設計思想およびUIの一貫性を保ち、簡潔で視認性が高く、開発者の思考を妨げない設計ツールとする。

## 対象範囲

### 対象

- VS Code拡張機能としての提供
- `.gls`形式の独自DSLによる設計情報の定義
- 状態の名称、意味、カラー、表示順序の管理
- イベントと階層的なカテゴリの管理
- 状態とイベントに対応した処理・遷移先・条件分岐の管理
- 状態定義・状態遷移図・状態遷移表の統合表示
- React Flowによる状態遷移の可視化
- DSLで指定する複数状態のグループ化と遷移表現
- 状態遷移表によるイベントと状態の組み合わせの可視化
- 未定義の状態遷移の明示
- 状態選択に連動した表示領域間の強調
- DSLの変更に追従する自動プレビュー更新
- DSLの構文・参照・定義整合性の検証
- 状態遷移図の拡大・縮小と画像エクスポート
- VS Codeのテーマに対応したUI
- 設計情報をローカルファイルで管理する仕組み

### 対象外

- 状態遷移そのものを実行するランタイム機能
- 実行中アプリケーションの状態監視
- DSLからのアプリケーションコード自動生成
- 外部サービスやデータベースとの常時同期
- プロジェクト管理機能(GlitchBoardの領域)
- シーケンス図・DB/FILE状態の設計(GlitchFlowの領域)

## 用語

用語は、必要になったら追加する。

| 用語 | 意味 |
| --- | --- |
| DSL | 状態とイベント、処理、遷移を定義する独自記法 |
| 状態定義 | 状態名、意味、カラー、順序の定義 |
| イベント | 状態に対して発生する事象 |
| イベントカテゴリ | イベントを階層的に分類する単位 |
| 状態遷移 | イベントや条件に応じた状態の変化 |
| 状態遷移図 | 状態間の遷移関係を図示したもの |
| 状態遷移表 | イベントを行、状態を列として処理・遷移を表すマトリクス |
| グループ | DSLで指定した複数状態を図上でまとめる表示単位 |
| 未定義 | 対象の状態とイベントの組み合わせに対して定義が存在しないこと |

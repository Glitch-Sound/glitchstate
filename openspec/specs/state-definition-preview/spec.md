# state-definition-preview Specification

## Purpose

開発者がVS Codeで編集中の`.gls`ファイルから状態定義表を確認し、保存操作を挟まず設計内容を見直せるように、プレビューの対象、表の内容、自動更新、解析エラー時の表示を定める。

## Requirements

### Requirement: REQ-003 - 対象文書のプレビューを開く

WHEN `.gls`文書がアクティブな状態で`glitchstate.openPreview`コマンドを実行したとき、VS Code拡張機能は、その文書の保存前を含む現在の内容をプレビューへ表示しなければならない(SHALL)。\
プレビューは単一とし、再実行では既存の画面を使い、別の`.gls`文書から実行した場合は対象を切り替える。\
`.gls`文書がアクティブでない場合はプレビューの新規作成や対象の変更を行わない。

#### Scenario: REQ-003-S01 - 保存前の内容でプレビューを開く

- **GIVEN** `design.gls`の保存済みの状態名が`待機`で、アクティブな文書では未保存の`開始待ち`に変更している。
- **WHEN** `glitchstate.openPreview`を実行する。
- **THEN** プレビューの状態名は`開始待ち`であり、`待機`の行はない。

#### Scenario: REQ-003-S02 - 既存のプレビューの対象を切り替える

- **GIVEN** A.glsのプレビューを表示し、B.glsには異なる状態定義がある。
- **WHEN** B.glsをアクティブにして`glitchstate.openPreview`を実行する。
- **THEN** プレビューは1つのままで、表はB.glsの状態定義だけになる。

#### Scenario: REQ-003-S03 - 対象外の文書から開かない

- **GIVEN** アクティブな文書がない、またはアクティブな文書が`.gls`ではない。
- **WHEN** `glitchstate.openPreview`を実行する。
- **THEN** 新しいプレビューは作成されず、既存のプレビューがある場合は対象も表も変化しない。

#### Scenario: REQ-003-S04 - 小さい版番号で再オープンした文書をコマンドで表示する

- **GIVEN** プレビュー対象の`.gls`を閉じ、同じURIを閉じる前より小さい版番号で開き直し、プレビューを開いたままにしている。
- **WHEN** 再オープンした文書をアクティブにして`glitchstate.openPreview`を実行する。
- **THEN** 既存の単一プレビューに再オープンした文書の現在の状態定義が表示され、閉じる前の表は残らない。

### Requirement: REQ-004 - 状態定義表の表示

WHEN 有効な状態定義を表示するとき、プレビューは、左から色、状態、意味の3列を持つ表に、状態を定義順の行として表示しなければならない(SHALL)。\
色列は指定カラーの色見本のみを表示し、カラー値の文字列を表示しない。\
状態列は状態名、意味列は意味を表示する。\
意味の改行を保ち、DSLの文字列は表示用テキストとして扱う。\
状態が0件の場合は表に状態行を表示せず、状態がないことを示す。\
表の基本の文字、背景、罫線はVS Codeの明暗テーマに追従し、指定カラーは状態の色見本に使用する。

#### Scenario: REQ-004-S01 - 状態の内容と定義順を表に反映する

- **GIVEN** 最初に`Z_LAST`の状態名`待機`、意味`開始を待つ状態`、カラー`#4F46E5`を定義し、次に`A_FIRST`の状態名`実行中`、意味`処理中`、カラー`#22c55e`を定義している。
- **WHEN** プレビューを表示する。
- **THEN** 列見出しは左から`色`、`状態`、`意味`の3列である。
- **AND** 1行目の色セルは`#4F46E5`の色見本のみ、状態セルは`待機`、意味セルは`開始を待つ状態`である。
- **AND** 2行目の色セルは`#22c55e`の色見本のみ、状態セルは`実行中`、意味セルは`処理中`である。
- **AND** 各行の色セルにはカラー値を含む表示用テキストがない。

#### Scenario: REQ-004-S02 - 空の定義を表に反映する

- **GIVEN** 状態を1件表示していた文書から定義をすべて削除した。
- **WHEN** プレビューが更新される。
- **THEN** 状態行は0件となり、状態がないことが表示され、古い行は残らない。

#### Scenario: REQ-004-S03 - 意味を実行せず改行付きの文字列として表示する

- **GIVEN** 意味の1行目が`<script>window.glsExecuted = true</script>`で、2行目が`確認する`である。
- **WHEN** プレビューを表示する。
- **THEN** 2行の文字列がそのまま表示され、`script`要素は生成されず、`window.glsExecuted`は設定されない。

#### Scenario: REQ-004-S04 - VS Codeのテーマに追従する

- **GIVEN** 指定カラー付きの状態定義表を表示している。
- **WHEN** VS Codeの明暗テーマを切り替える。
- **THEN** 表の基本の文字、背景、罫線が選択したテーマに追従し、状態名と意味を読み取れる。
- **AND** 状態の色見本はDSLで指定した色を保つ。

### Requirement: REQ-005 - 保存前の変更への追従

WHEN プレビュー対象の`.gls`文書が編集されたとき、VS Code拡張機能は、保存や手動更新を要求せず現在の内容をプレビューへ反映しなければならない(SHALL)。\
別の文書の編集で対象を切り替えず、最新より古い解析結果で表や診断を上書きしてはならない。\
プレビューの起動準備中に変更された場合も、表示開始時に最新の内容を表示する。

#### Scenario: REQ-005-S01 - 各項目と定義順の編集を保存前に反映する

- **GIVEN** 2件の状態をプレビューし、ファイル保存を行わない。
- **WHEN** 次の編集のいずれかを行う。

  | 編集 | 期待する結果 |
  | --- | --- |
  | 状態名を`開始待ち`にする | 対象行の状態名が`開始待ち`になる |
  | 意味を`要求の到着を待つ`にする | 対象行の意味が`要求の到着を待つ`になる |
  | カラーを`#FF8800`にする | 対象行の色見本が`#FF8800`になり、色セルに表示用テキストはない |
  | 2件の宣言と本文を入れ替える | 行順が逆になる |
  | 状態を1件追加する | 追加した位置に1行増える |
  | 状態を1件削除する | 対象行が消え、残りの状態だけになる |

- **THEN** 手動更新なしで表の期待する結果になり、文書は未保存のままである。

#### Scenario: REQ-005-S02 - 別の文書の編集を混入させない

- **GIVEN** A.glsをプレビューしている。
- **WHEN** 別のB.glsを編集する。
- **THEN** プレビュー対象はA.glsのままで、その表と診断はB.glsの内容で置き換わらない。

#### Scenario: REQ-005-S03 - 古い結果で最新の表示を上書きしない

- **GIVEN** 同じ文書を続けて編集し、新しい内容の表と診断がすでに反映されている。
- **WHEN** 古い内容の解析結果が遅れて利用可能になる。
- **THEN** 新しい内容の表と診断が保たれ、古い状態名やエラーに戻らない。

#### Scenario: REQ-005-S04 - 起動準備中の編集を表示開始時に反映する

- **GIVEN** プレビューを開き始めた時点の状態名が`待機`であり、表示準備が完了する前に未保存の`開始待ち`へ変更した。
- **WHEN** プレビューが表示可能になる。
- **THEN** 状態名は`開始待ち`と表示され、変更を反映するための追加の編集や再表示を必要としない。

#### Scenario: REQ-005-S05 - 小さい版番号で再オープンした後も自動更新する

- **GIVEN** プレビュー対象の`.gls`を閉じ、同じURIを閉じる前より小さい版番号で開き直し、プレビューを開いたままにしている。
- **WHEN** コマンドを再実行せず、再オープンした文書の状態名を保存前の`再オープン後の編集`へ変更する。
- **THEN** 閉じる前より版番号が小さいままでも、同じプレビューの状態名が`再オープン後の編集`へ自動更新される。
- **AND** 文書は未保存のままで、閉じる前の状態名は表示されない。

### Requirement: REQ-006 - 解析エラー時の診断と表示の保持

IF プレビュー対象の内容に解析エラーがある場合、THEN VS Code拡張機能は、エラーの位置と理由をProblemsへ通知し、同じ文書の最後の正常な表を保持しなければならない(SHALL)。\
正常な表をまだ表示したことがない文書では、表の代わりに解析エラーで表示できないことを示し、別の文書の表を保持しない。\
正常な内容に修正されたら現在の表へ更新し、解消した診断を削除する。

#### Scenario: REQ-006-S01 - 編集途中のエラーで正常な表を失わない

- **GIVEN** 状態名`待機`の正常な表を表示している。
- **WHEN** 対象文書のカラーを`red`に変更する。
- **THEN** Problemsにその宣言行のカラーのエラーが表示される。
- **AND** 表は直前の正常な状態名`待機`と元のカラーを保ち、不正な`red`を色として反映しない。

#### Scenario: REQ-006-S02 - 最初から不正な文書で別の表を表示しない

- **GIVEN** 正常なA.glsをプレビューし、B.glsは意味を欠いた状態定義で、一度も正常に表示されていない。
- **WHEN** B.glsからプレビューを開く。
- **THEN** B.glsの宣言行に意味がないことを示す診断が表示される。
- **AND** プレビューにA.glsの状態行はなく、解析エラーで表示できないことが示される。

#### Scenario: REQ-006-S03 - 修正後に表と診断を回復する

- **GIVEN** 対象文書にカラーのエラーがある。
- **WHEN** 保存せずにカラーを`#0088FF`へ修正する。
- **THEN** 表の色見本は`#0088FF`へ更新され、色セルに表示用テキストはなく、解消した診断と表示不能の案内は残らない。

### Requirement: REQ-034 - 状態定義表を起点とする単一選択

WHEN 表示中の状態定義表で状態を選択するとき、プレビューは、その状態IDだけを選択し、行全体とREQ-036のノード、REQ-037の状態列を薄い背景色で強調しなければならない(SHALL)。\
初期状態は未選択とし、別行の選択で切り替え、同じ行の再選択とプレビュー内のEscapeで解除する。\
行のクリックと、Tabで到達できる状態名の操作対象のEnterまたはSpaceを受け付け、選択の有無を支援技術から判別可能にする。\
選択を示す枠線と外周の影を付けず、フォーカスは選択と区別して示す。\
明暗テーマに追従し、状態の指定カラーと色見本、未定義の赤文字、既存の表と分岐とグループの線を保つ。\
状態がない場合は選択対象を作らず、図と状態遷移表から選択状態を切り替えない。

#### Scenario: REQ-034-S01 - 未選択から行全体を選択する

- **GIVEN** 状態AとBの3表示を新しく開き、選択中の状態はない。
- **WHEN** 状態定義表のAの行をクリックする。
- **THEN** Aだけが選択中として判別可能になり、色、状態、意味を含むAの行全体の背景が変わり、Bの行の背景は変わらない。
- **AND** 列は色、状態、意味の3列のままで、色セルに表示用テキストと選択用の追加列はない。

#### Scenario: REQ-034-S02 - 同名状態でも別行で単一選択を切り替える

- **GIVEN** 異なるIDのAとBが同じ状態名で、Aだけを選択している。
- **WHEN** 状態定義表のBの行をクリックする。
- **THEN** Bだけが選択中になり、Aの行とノードと列の選択表示は解除され、同名による同時選択や統合はない。

#### Scenario: REQ-034-S03 - 再選択またはEscapeで3表示を解除する

- **GIVEN** 状態Aを選択している。
- **WHEN** 次のいずれかを行う。

  | 操作 | 期待する選択 |
  | --- | --- |
  | 状態定義表のAの行を再クリック | 未選択 |
  | プレビュー内でEscapeを押す | 未選択 |

- **THEN** 選択中の状態はなく、行、ノード、状態列のすべてが選択前の背景へ戻り、表や図の内容は変わらない。

#### Scenario: REQ-034-S04 - キーボードで選択と解除を操作する

- **GIVEN** 状態名の操作対象へTabで移動できる状態定義表がある。
- **WHEN** 次のいずれかの操作を行う。

  | 前提 | 操作 | 期待する結果 |
  | --- | --- | --- |
  | 未選択でAへフォーカス | Enter | Aだけを選択 |
  | Aを選択しBへフォーカス | Space | Bだけを選択 |
  | Aを選択しAへフォーカス | Space | 未選択 |
  | Aを選択しAへフォーカス | Escape | 未選択 |

- **THEN** 表の結果が行、ノード、状態列へ同じIDで反映され、フォーカスだけの行を選択中と表示せず、キーボードフォーカスは読み取れる。

#### Scenario: REQ-034-S05 - 明暗テーマでも背景だけで選択を示す

- **GIVEN** 指定カラーの状態と未定義セル、分岐の縦線、グループ枠を持つ3表示がある。
- **WHEN** 明テーマまたは暗テーマで状態Aを選択する。
- **THEN** 選択行、Aのノード、Aの列の背景を非選択と区別でき、選択を示す新しい枠線と外周の影はない。
- **AND** 色見本と状態名の指定カラー、未定義の赤文字、既存の罫線と分岐の縦線、グループ枠の実線は選択前と一致し、文字と処理を読み取れる。

#### Scenario: REQ-034-S06 - 状態がない文書に選択対象を作らない

- **GIVEN** 状態が0件の有効な文書を表示している。
- **WHEN** プレビューを操作する。
- **THEN** 状態選択の操作対象と選択表示はなく、状態がないことの案内が表示される。

### Requirement: REQ-035 - 対象文書と状態IDによる選択の保持と解除

WHEN プレビューの内容が更新されるとき、プレビューは、同一対象文書の表示モデルに選択中の状態IDが存在する限り、その選択を保持しなければならない(SHALL)。\
名前、カラー、意味、定義順、所属、イベントと遷移の変更や、解析エラーで直前の正常表示を保持する場合も同じIDを選択する。\
正常モデルからのIDの削除と変更、状態0件、正常表示のないモデル、対象文書の切替で解除し、同名状態へ移さず、同じIDの再追加や元の文書への復帰で自動復元しない。\
同じプレビューとURIでの小さい版番号による再オープンとコマンド再実行ではIDによる保持を適用し、プレビューを作り直した場合は未選択から始める。\
古い通知と不正な通知では選択を変更せず、選択によってDSLと診断を変更しない。

#### Scenario: REQ-035-S01 - 同じIDの編集で選択を保つ

- **GIVEN** AとBがあり、Aを選択している。
- **WHEN** 保存せず、次のいずれかを有効なまま変更する。

  | 編集 | 期待する結果 |
  | --- | --- |
  | Aの名前、意味、カラー | Aの現在の行とノードと列で新しい内容を表示して選択を保持 |
  | AとBの定義順 | 移動後のAだけを選択し、以前の位置のBは非選択 |
  | Aのグループ所属 | 移動後のAだけを選択し、枠と他のメンバーは非選択 |
  | イベントの分類と見出し、処理と分岐と遷移先 | 現在の各セルを表示し、選択状態はAのまま |

- **THEN** 名前や位置に付け替えず、現在のAだけに3表示の選択がそろい、文書は未保存のままである。

#### Scenario: REQ-035-S02 - 参照エラーで保持し異なる現在の内容へ回復する

- **GIVEN** Aを選択した正常表示の後、遷移先を未宣言IDへ変え、診断とエラー案内を表示して直前の正常な3表示を保持している。
- **WHEN** AのIDを保ち、状態名、カラー、順序、処理、分岐の条件と遷移先を以前と異なる有効な内容へ修正する。
- **THEN** エラー中も修正後もAだけの選択が維持され、回復した3表示はすべて現在の異なる内容となり、診断とエラー案内は消える。
- **AND** 正常表示を保持している間の選択操作も表示中の状態に対して行える。

#### Scenario: REQ-035-S03 - IDが消えたら解除し再追加で復元しない

- **GIVEN** Aを選択し、Bも表示している。
- **WHEN** 次のいずれかの正常な内容へ更新する。

  | 編集 | 期待する選択 |
  | --- | --- |
  | Aとその参照を削除 | 未選択 |
  | AのIDと参照だけをCへ変更し名前は維持 | 未選択 |
  | 全状態を除去 | 未選択 |

- **THEN** 3表示に選択が残らず、Bや同名状態へ移らず、後からAを再追加しても再度選択するまでは未選択である。

#### Scenario: REQ-035-S04 - 同じIDの別文書へ選択を持ち越さない

- **GIVEN** A.glsで状態IDLEを選択し、B.glsも同じIDと異なる内容を持つ、または正常表示がない文書である。
- **WHEN** B.glsからプレビューコマンドを実行する。
- **THEN** B.glsの表示または表示不能の案内にA.glsの選択が残らず、B.glsは未選択である。
- **AND** A.glsへ対象を戻しても以前の選択は自動復元しない。

#### Scenario: REQ-035-S05 - 古い通知と不正な通知で選択を戻さない

- **GIVEN** 最新の正常表示でBを選択している、またはAの削除後に未選択になっている。
- **WHEN** 古い通知順のモデル、または新しい通知順でも形式が不正なモデルが届く。
- **THEN** 現在の内容とBの選択、または削除後の未選択が保持され、通知に含まれるAや別文書の選択へ変わらない。

#### Scenario: REQ-035-S06 - 同じURIの再オープンでIDによる選択を維持する

- **GIVEN** プレビューを残し、選択したAが存在する同じURIを閉じる前より小さい版番号で開き直している。
- **WHEN** Aの名前を未保存で変更する、または同じ文書からプレビューコマンドを再実行する。
- **THEN** 現在の名前のAだけが3表示で選択され、版番号の低下とコマンド再実行による解除や以前の名前への回帰はない。

#### Scenario: REQ-035-S07 - 新しいプレビューでは未選択に戻す

- **GIVEN** 状態Aを選択したプレビューを閉じている。
- **WHEN** 同じ文書のプレビューを新しく作る。
- **THEN** 状態の内容は表示され、Aを含めて選択中の状態はなく、以前の選択は復元されない。

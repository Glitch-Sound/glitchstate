# 差分仕様

## ADDED Requirements

### Requirement: REQ-030 - 所属状態を囲む名前付きの実線枠

WHEN 有効な状態グループをプレビューするとき、状態遷移図は、グループ名を持つ実線の枠で所属する状態ノードだけを囲み、個々の状態名と指定カラーを保持しなければならない(SHALL)。\
同名の状態とグループはIDで区別し、未所属状態はどの枠にも含めず、各グループと未所属状態の領域を重ねない。\
所属状態は状態の定義順に配置し、枠内に名前と状態、内部の自己ループを欠落なく収め、グループ名は表示用テキストとして扱う。\
状態定義表と状態遷移表の間という配置とテーマに沿う表示を保ち、グループ宣言がなければ既存の図を維持する。\
状態とグループの選択連動や操作ボタンを追加しない。

#### Scenario: REQ-030-S01 - 指定した状態だけを実線の枠で囲む

- **GIVEN** 定義順が`A`、未所属`X`、`B`、`C`の状態があり、グループ`G`(稼働系)の所属は`C`、`A`、`B`の順で指定している。
- **WHEN** 図を表示する。
- **THEN** `稼働系`の実線枠は1つで、内部の状態は定義順の`A`、`B`、`C`の各1件であり、それぞれの名前と指定カラーが保たれる。
- **AND** `X`は枠外にあり、枠は状態定義表と状態遷移表の間にだけ表示される。

#### Scenario: REQ-030-S02 - 同名グループと名前の文字列を区別する

- **GIVEN** 異なるIDのグループ2件が同じ名前`<b>稼働系</b>`で、それぞれの所属状態は異なり、同名状態もある。
- **WHEN** 図を表示する。
- **THEN** 同名グループの実線枠は2つで重ならず、状態の統合と混入はなく、グループ名の文字列は各枠にそのまま表示され、b要素は作られない。

#### Scenario: REQ-030-S03 - 長い名前と実測した状態とループを枠に収める

- **GIVEN** 折り返しが必要な長いグループ名と複数行の状態名、上へ張り出す自己ループを持つグループと、別グループと未所属状態がある。
- **WHEN** 図の配置が完了する。
- **THEN** グループ名の末尾、所属状態の全領域と自己ループの経路が枠内に収まり、名前と状態は重ならず、別グループと未所属状態は枠外である。
- **AND** 枠とノード、矢印は図領域内へ収まり、長い内容を省略せず、選択連動と追加の操作ボタンはない。

#### Scenario: REQ-030-S04 - グループの除去で従来の図へ戻す

- **GIVEN** グループ枠と所属状態を表示している。
- **WHEN** 有効なままグループ宣言だけをすべて除去する。
- **THEN** 枠とグループ名は残らず、全状態の名前とカラー、定義順の配置は同じ内容のグループなし文書と一致する。

### Requirement: REQ-031 - 複数の所属状態から同一外部状態への矢印集約

WHEN 図の矢印を表示するとき、状態遷移図は、同じグループの異なる2状態以上から同じグループ外の状態へ向く遷移を、グループ枠からその状態へ向く1本に集約しなければならない(SHALL)。\
グループと到達先ごとに、イベントと分岐、処理の有無によらず異なる遷移元状態を数え、全メンバーの一致を要求しない。\
集約した個別矢印は残さず、1状態だけからの遷移、グループ内への遷移、自己遷移はREQ-015とREQ-026に従い、遷移なしは矢印を作らない。\
1状態から複数状態への矢印はまとめず、到達先が別グループに所属していても終点は個々の状態とする。\
淡い線と矢尻、ラベルなしを保ち、すべての矢尻を経路終端の進行方向へ向ける。

#### Scenario: REQ-031-S01 - 一部のメンバーだけの共通到達先も枠から1本にする

- **GIVEN** グループ`G`に`A`、`B`、`C`が所属し、`A`と`B`から外部状態`X`へ遷移し、`C`にはXへの遷移がない。
- **WHEN** 図を表示する。
- **THEN** `G`の実線枠の境界を始点、`X`の状態ノードを矢尻の終点とする矢印が1本あり、AからXとBからXの個別矢印はない。
- **AND** CからXの遷移定義は作られず、イベント名、条件名と処理のラベルはない。

#### Scenario: REQ-031-S02 - イベントと分岐をまたいで異なる遷移元を数える

- **GIVEN** GにAとBが所属し、AはSTARTの分岐なし遷移でXへ、BはRETRYの2番目の分岐で処理なしでXへ向かい、ほかの分岐はYへ向かう。
- **WHEN** 図を表示する。
- **THEN** GからXへ1本、BからYへ1本があり、2番目の分岐と処理なしの遷移を省略せず、元のAからXとBからXの矢印を重ねない。

#### Scenario: REQ-031-S03 - 同じ1状態の重複遷移では枠を始点にしない

- **GIVEN** GにAとBが所属し、Aだけが異なるイベントと複数の分岐でXへ遷移し、BからXの遷移はない。
- **WHEN** 図を表示する。
- **THEN** AからXへの矢印だけが1本あり、遷移定義の件数によってGからXへの矢印を作らない。

#### Scenario: REQ-031-S04 - 内部遷移と自己遷移となしを集約しない

- **GIVEN** GにA、B、Cが所属し、AからC、BからC、AからA、Bから遷移なしがある。
- **WHEN** 図を表示する。
- **THEN** AからCとBからCの各1本、Aの外側からAへ戻る自己ループ1本だけがあり、GからCやGからGの矢印と、なしからの矢印はない。

#### Scenario: REQ-031-S05 - 到達先と遷移元グループを混同せず逆向きの集約をしない

- **GIVEN** GはA、B、Cを持ち、HはX、Yを持ち、AとBからX、AだけからY、未所属UからXとY、別グループJの2状態からXへ遷移している。
- **WHEN** 図を表示する。
- **THEN** Gから状態X、状態Aから状態Y、状態Uから状態Xと状態Y、Jから状態Xへの5本だけがある。
- **AND** Hの枠を終点とする矢印や、GとJを1つの始点へまとめた矢印はなく、Xへの集約に無関係なGのCからの遷移は作られない。

#### Scenario: REQ-031-S06 - 集約された往路と個別の復路の方向を保つ

- **GIVEN** GのAとBから外部Xへ向かう遷移と、XからAへ戻る遷移がある。
- **WHEN** 図を表示する。
- **THEN** Gの枠からXへ向かう1本と、XからAへ戻る1本があり、経路は完全には重ならず、それぞれの矢尻の向きは経路終端の進行方向と一致する。
- **AND** グループ内の自己ループと通常の個別矢印も、それぞれの状態を終点として矢尻の向きを保つ。

### Requirement: REQ-033 - 編集中のグループと3表示の整合

WHEN 対象文書のグループまたは所属状態に関係する定義を編集するとき、プレビューは、REQ-017とREQ-027の更新と診断の規則をグループにも適用し、保存前の同じ内容へ枠と矢印、両表を追従させなければならない(SHALL)。\
グループの追加と除去、名前と所属、個々の遷移先の変更で枠と集約を再判定する。\
誤りでは同じURIの正常な3表示を保持し、修正後は現在の異なる内容へ回復して診断と案内を消す。\
古い通知と不正なグループモデル、別文書を混入させず、小さい版番号での再オープンと図の準備中の変更でも、現在の枠と矢印と両表がそろってから現在の描画完了だけを通知する。

#### Scenario: REQ-033-S01 - 所属と遷移を未保存で変更して枠と集約を更新する

- **GIVEN** 分類と条件分岐を持ち、GのAとBから外部Xへ向かう正常な3表示を開いている。
- **WHEN** 次のいずれかの編集を保存せずに行う。

  | 編集 | 期待する図 |
  | --- | --- |
  | グループの追加または除去 | 指定した枠と名前だけが増減し、個別と集約の矢印が切り替わる |
  | グループ名だけを変更 | 名前だけが変わり、所属と到達先は不変 |
  | BをGから別グループへ移す | 枠の所属が変わり、Xへの遷移元が1状態の各グループでは個別矢印となる |
  | BからXを別状態またはなしへ変更 | Xへの集約は解除され、残る個別矢印と現在の到達先だけを表示 |
  | 別メンバーからXへの遷移を追加 | GからXへの1本に戻る |

- **THEN** 手動更新なしで表の結果となり、両表は個々の現在の状態と遷移、分類と分岐を保ち、文書は未保存のままである。

#### Scenario: REQ-033-S02 - 所属エラーで保持して異なる現在の内容へ回復する

- **GIVEN** G(稼働系)はAとBを囲みXへ集約し、分類と共通処理と分岐、状態名を持つ正常な3表示がある。
- **AND** Gの所属をMISSINGへ変えており、所属行の参照診断とエラー案内があり、直前の正常な3表示を保持している。
- **WHEN** 保存せず、名前を復旧系、所属をBとC、到達先を別状態Y、状態名と共通処理と条件と処理、分類と列見出しを以前と異なる有効な内容へ修正する。
- **THEN** 復旧系の枠はBとCだけを囲み、Yへの集約矢印と個別の遷移を含む両表の全変更が現在の内容となり、診断と案内は消え、文書は未保存のままである。

#### Scenario: REQ-033-S03 - 古い通知と不正なグループモデルを受理しない

- **GIVEN** 最新のグループと個別遷移を持つ正常な3表示がある。
- **WHEN** 古い通知順の有効なモデル、または新しい通知順で次の1項目だけが不正な通知が届く。

  | 項目 | 不正な内容 |
  | --- | --- |
  | グループ一覧 | 配列以外、null |
  | グループIDと名前 | 欠落、型違い、不正なID、空白だけや引用符と改行を含む名前、IDの重複 |
  | 所属状態 | 欠落、配列以外、null、2件未満、文字列以外、不正なID、未宣言の状態、同じグループ内の重複、複数グループへの重複所属 |
  | グループの要素 | 余分な入れ子や状態と遷移を埋め込んだ項目 |

- **THEN** 現在の枠と実矢印、両表と診断を保ち、グループを読み飛ばして新しい表示へ進んだり、不正な通知の描画完了を送ったりしない。

#### Scenario: REQ-033-S04 - 小さい版番号の再オープン後もグループを更新する

- **GIVEN** 単一プレビューを残して文書を閉じ、同じURIを閉じる前より小さい版番号で開き直している。
- **WHEN** コマンドを再実行せずグループと遷移を未保存で変更する、または再オープンした文書からプレビューコマンドを再実行する。
- **THEN** 両操作とも同じ単一プレビューの枠と集約矢印、両表が現在の異なる内容となり、閉じる前の所属と矢印は残らない。

#### Scenario: REQ-033-S05 - 別文書のグループと正常表示を混ぜない

- **GIVEN** A.glsの正常なグループ付き3表示があり、B.glsには正常履歴がなくグループの参照エラーがある。
- **WHEN** B.glsを編集するだけ、またはB.glsからプレビューコマンドを実行する。
- **THEN** 編集だけなら対象と3表示と診断はAのままであり、コマンドならBの所属行の診断と表示できない案内になり、Aの枠と矢印、両表は残らない。

#### Scenario: REQ-033-S06 - 枠の計測中の変更を現在の描画完了に反映する

- **GIVEN** グループ名と所属状態の計測が終わる前に、グループ名、所属、共通処理と到達先を変更している。
- **WHEN** 現在の枠と矢印の配置が完了する、または以前の配置の完了が遅れて届く。
- **THEN** 最初の完了通知時点で現在の名前と所属だけを囲む枠、境界から現在の到達先への非零長の矢印、両表がそろい、現在のURIと版番号と通知順に対応する完了だけを送り、古い枠と矢印へ戻らない。

## MODIFIED Requirements

### Requirement: REQ-014 - 状態定義表と状態遷移表の間の状態ノード

WHEN 有効な文書をプレビューするとき、プレビューは、状態定義表と状態遷移表の間に状態遷移図を表示し、各状態IDに対応するノードへ状態名と指定カラーを反映しなければならない(SHALL)。\
同じ状態名でも異なるIDのノードを統合せず、遷移やイベントを持たない状態も表示する。\
状態名は表示用テキストとして扱い、状態グループの枠と所属状態の表示はREQ-030に従う。\
状態が0件の有効な文書ではノードと矢印を表示せず、状態がないことを案内し、以前の図を残さない。

#### Scenario: REQ-014-S01 - 2表の間に名前と指定色を持つノードを表示する

- **GIVEN** 状態`Z_IDLE`(待機、`#4F46E5`)、`A_RUN`(実行中、`#22C55E`)を定義している。
- **WHEN** プレビューを開く。
- **THEN** 上から状態定義表、状態遷移図、状態遷移表の順で表示される。
- **AND** 図には`待機`と`実行中`のノードが各1件あり、それぞれのノードに対応する指定カラーが使われ、名前の代わりにIDは表示されない。

#### Scenario: REQ-014-S02 - 同じ名前でも状態IDを区別する

- **GIVEN** 異なるIDの状態2件の名前がともに`待機`で、それぞれから異なる状態への遷移がある。
- **WHEN** 図を表示する。
- **THEN** `待機`のノードは2件あり、それぞれの矢印は遷移元IDに対応するノードから出て、名前によって1件へ統合されない。

#### Scenario: REQ-014-S03 - イベントや遷移のない状態も表示する

- **GIVEN** 状態2件があり、次のいずれかの内容である。

  | 内容 | 期待する図 |
  | --- | --- |
  | イベントも遷移もない | 状態ノード2件、矢印0本 |
  | イベントがあり遷移がない | 状態ノード2件、矢印0本 |
  | 1件の状態だけに自己遷移がある | 状態ノード2件、自己ループ1本 |

- **WHEN** 図を表示する。
- **THEN** 図は表の結果となり、遷移のない状態が欠落しない。

#### Scenario: REQ-014-S04 - 状態がなくなったら古い図を消す

- **GIVEN** ノードと矢印を持つ図を表示している。
- **WHEN** 文書を空にする、またはイベントだけの有効な内容へ変更する。
- **THEN** 図領域には状態がないことの案内があり、ノードと矢印は0件で、以前の状態名は残らない。

#### Scenario: REQ-014-S05 - 状態名を文字列として表示する

- **GIVEN** 状態名に`<script>window.glsDiagramExecuted = true</script>`を持つ状態と、`<b>待機</b>`を持つ状態がある。
- **WHEN** 図を表示する。
- **THEN** 両方の名前の文字列がそのまま表示され、図内に`script`要素や`b`要素は生成されず、`window.glsDiagramExecuted`は設定されない。

### Requirement: REQ-015 - 状態間の方向付き矢印

WHEN 状態遷移図を表示するとき、図は、分岐なし遷移とREQ-026の各分岐が持つ遷移先状態IDを遷移元ノードから遷移先ノードへの矢印として表示しなければならない(SHALL)。\
処理の有無によらず遷移先で矢印の有無を決め、遷移なしと未定義の組み合わせには矢印を作らない。\
同じ遷移元IDと遷移先IDの組み合わせはイベントが異なっても1本にまとめ、逆方向は別の矢印とする。\
自状態への遷移は外側へ張り出して同じノードへ戻る自己ループとし、相互の矢印は方向を区別できる経路にする。\
イベント名、条件名と処理のラベルは表示しない。\
REQ-031の集約対象だけは遷移元ノードの代わりにグループ枠を始点とし、到達先は個々の状態ノードのままにする。

#### Scenario: REQ-015-S01 - 遷移先へ向く矢印をラベルなしで表示する

- **GIVEN** 状態`IDLE`と`RUNNING`があり、イベント`START`(開始要求)に対して`IDLE`から`RUNNING`へ処理`開始を記録する`を定義している。
- **WHEN** 図を表示する。
- **THEN** 矢印は1本で、始点は`IDLE`のノード、終点の矢尻は`RUNNING`のノードにある。
- **AND** 図には`開始要求`、`START`、`開始を記録する`のラベルがない。

#### Scenario: REQ-015-S02 - 遷移なしと未定義を矢印へ変換しない

- **GIVEN** 状態`IDLE`、`RUNNING`とイベント`START`があり、対象の組み合わせは次のいずれかである。

  | 定義 | 期待する矢印 |
  | --- | --- |
  | 処理なし、遷移先RUNNING | IDLEからRUNNINGへの1本 |
  | 処理あり、遷移なし | 0本 |
  | 処理なし、遷移なし | 0本 |
  | 定義がない | 0本 |

- **WHEN** 図を表示する。
- **THEN** 矢印は表の結果となり、遷移なしや未定義から自己ループは作られない。

#### Scenario: REQ-015-S03 - 同じ向きの状態間の関係をまとめる

- **GIVEN** 異なるイベント`START`、`RETRY`でともに`IDLE`から`RUNNING`へ遷移し、処理は異なっている。
- **WHEN** 図を表示する。
- **THEN** `IDLE`から`RUNNING`への矢印は1本だけで、イベントや処理の違いによって重複しない。
- **AND** 状態遷移表では各イベントの処理と遷移先が別々のセルに保持される。

#### Scenario: REQ-015-S04 - 自状態への遷移を自己ループで示す

- **GIVEN** 異なるイベント2件でともに`IDLE`から`IDLE`へ遷移している。
- **WHEN** 図を表示する。
- **THEN** `IDLE`から出てノード外側を通り、矢尻が`IDLE`へ戻る自己ループが1本あり、長さ0の線や別の状態への矢印にはならない。

#### Scenario: REQ-015-S05 - 相互の遷移を区別する

- **GIVEN** `IDLE`から`RUNNING`と、`RUNNING`から`IDLE`の遷移がある。
- **WHEN** 図を表示する。
- **THEN** 矢印は2本あり、それぞれの終点に矢尻があり、経路が完全には重ならず、両方向の存在を確認できる。

### Requirement: REQ-026 - 各分岐の到達先を状態間の矢印へ反映する

WHEN 分岐付き遷移を図に表示するとき、図は、各分岐の遷移先状態IDを元の状態からの有向ペアへ変換し、REQ-015の矢印として表示しなければならない(SHALL)。\
共通処理と各分岐の処理の有無によらずすべての分岐を対象とし、同じ有向ペアは分岐とイベント、分岐の有無をまたいで1本へまとめる。\
REQ-031のグループ集約条件を満たす有向ペアだけは枠から到達先への1本にまとめ、個々の分岐定義は維持する。\
